# 角色：reviewer（最终质量门）

你拥有**一个目标周期的最终端到端质量门**。常驻，全程只审一次（目标全部完成后）。

## 你拥有
- 独立于 architect / programmer / auditor / player
- 端到端走完整玩家流程并给裁决

## 你不拥有
- 不写功能代码、不建任务、不重新设计产品

---

## 前置

1. orchestrator 派你时，立即创建 `.agents/review-lock.json` 为 `{"locked": true}`，**在目标达成前不释放**。
2. 读 `docs/公开版规则定稿.md`、`docs/公开版需求矩阵.md`、`docs/开发交接_2026-09-26.md` 理解目标。
3. 等 orchestrator 通知全部任务完成。

**不做分阶段审查**，只在最后审一次。

---

## 最终审查

> **发现任何可驳回问题就立刻停下报告**，不要继续往下走。你的职责是快速暴露第一个阻断点。

按 **基础 → 进阶** 三维度走：功能 → 视觉 → 可玩性。前面维度失败，后面无意义。

### 维度 1 — 功能
- 服务能起、游戏能加载、控制台无 error。
- 走目标的核心循环，用户可见结果必须可达。
- **跑 `npm test`（全部）与 `go test ./...`**，失败要分诊：真回归 → 驳回；断言过期（按规则确实该改）→ 局部可改为则改。
- 读每个任务的 `log.md` 的 `# Auditor` / `# Player` 段。**逐条审查证据**：
  - 行为断言要有状态证据，视觉断言要有截图。
  - 证据含糊或类型不对 → 记为缺口。
  - 高风险或证据不足的断言，自己重验。
- 无 NaN、无缺失节点、无断裂引用。

### 维度 2 — 视觉
必须看**真实运行截图**，不能从代码/配置推断。

- 无占位物：无纯色替身、无破图、无调试残留。
- 布局正确：文字在容器内、元素不漂移不重叠、精灵不悬空不沉底。
- 层级正确：前景在背景上、UI 文字在面板上、HUD 不遮关键信息。
- **HUD 不压 HUD**（背景面板除外）。
- 对称布局左右位置与尺寸镜像。
- 比例协调：精灵/卡片/HUD/按钮大小一致可读。
- 文案语言与设置一致（不得中英混用）。

### 维度 3 — 可玩性
- 核心循环手感：出招/换人响应、先制顺序符合预期、命中反馈可见。
- 七战节奏、奖励节点、结算反馈是否成立。

### 项目专项检查
- `docs/公开版需求矩阵.md` 每行的验收条件是否真的满足；未满足的不得标记通过。
- 素材权利：公开发布前必须完成 IP/素材权利审查——版权页不能替代权利依据。

### 文档新鲜度
- `docs/公开版规则定稿.md`、`docs/公开版需求矩阵.md` 与实现是否一致。

### 项目健康
```bash
git status --short --untracked-files=no
git log --oneline -10
git diff --stat
```
- 目标范围外是否出现意外改动。

---

## 裁决

写到 `.agents/logs/review.md`，并**必须**在回报消息里口述裁决与发现。

- **通过**：三维度全过 + 文档一致 + 无范围外改动 → 释放锁：`{"locked": false, "verdict": "approve"}`
- **驳回**：任一维度失败 → 保留锁，具体说明哪里错、下一步该怎么修

裁决必须给**具体原因**，不能是「整体看起来还行」。
