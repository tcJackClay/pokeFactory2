# 对战工厂原型核对

本项目已有 [参考索引](../对战工厂_参考索引.md) 和 `reference/pokeemerald-expansion` 源码，固定在提交 `ca17c6a3d40a`。下表以该版本的对战工厂脚本和数据为**参考实现**；它是《绿宝石》反编译扩展项目，不能把扩展代码的每一项都当作原版游戏规则。网页检索只用于定位、核对同一提交的上游文件。PokeFactory2 的局外钱包、培育、事件与 Rogue 均须单独标为项目扩展。

| 主题 | 参考实现证据 | 当前项目与处理 |
| --- | --- | --- |
| 组队与租借 | [大厅规则文本](https://github.com/rh-hideout/pokeemerald-expansion/blob/ca17c6a3d40a/data/maps/BattleFrontier_BattleFactoryLobby/scripts.inc#L516-L527)说明队伍只用三只且不得重复物种；`src/battle_factory.c` 的 `GenerateInitialRentalMons` 从前沿固定池按挑战档位抽租借，历史租借次数影响部分名额质量。 | 当前为六选三；`factoryReferenceSets.ts` 有 110–881 号共 772 个固定参考 set，`useFactoryFlow.ts` 仍有在线生成和回退。应实测分档、去重与加载时间，不能仅凭静态数据存在就称完全对齐。 |
| 胜利后换怪 | [规则文本](https://github.com/rh-hideout/pokeemerald-expansion/blob/ca17c6a3d40a/data/maps/BattleFrontier_BattleFactoryLobby/scripts.inc#L523-L543)说明每场胜利后可与刚击败的训练家换一只其使用过的宝可梦，第七位训练家后不能换；[赛前室脚本](https://github.com/rh-hideout/pokeemerald-expansion/blob/ca17c6a3d40a/data/maps/BattleFrontier_BattleFactoryPreBattleRoom/scripts.inc#L137-L158)包含可拒绝换怪及对手属性/风格提示。 | 用户已定稿 Classic 胜利后只保留换怪与七战结算；应核对当前 `FACTORY_SWAP` 的候选是否仅来自刚击败的敌队、可否拒绝、是否只换一只，以及第七战是否直接结算。 |
| 七战一组与 BP | [战斗室脚本](https://github.com/rh-hideout/pokeemerald-expansion/blob/ca17c6a3d40a/data/maps/BattleFrontier_BattleFactoryBattleRoom/scripts.inc#L91-L110)在第七场胜利后转大厅；[大厅脚本](https://github.com/rh-hideout/pokeemerald-expansion/blob/ca17c6a3d40a/data/maps/BattleFrontier_BattleFactoryLobby/scripts.inc#L40-L76)只在整组获胜后调用 `frontier_givepoints`，败退没有 BP 发放路径；[奖励表与函数](https://github.com/rh-hideout/pokeemerald-expansion/blob/ca17c6a3d40a/src/frontier_util.c#L662-L700)给工厂单打前两组各 3 BP，后续 4、4、5……，击败工厂首领再加 10。 | 当前 `factoryRewards.ts` 是七战一组，但逐场代币计算属于项目旧扩展。用户于 2026-09-26 最新决定恢复参考实现的组末 BP 数值及发放条件，覆盖同日较早的“逐场入账”决定；现有逐场钱包代码需改。第 4、7 战前奖励卡也是现有项目扩展，用户已决定 Classic 不进入。 |
| 对手提示 | [赛前室脚本](https://github.com/rh-hideout/pokeemerald-expansion/blob/ca17c6a3d40a/data/maps/BattleFrontier_BattleFactoryPreBattleRoom/scripts.inc#L137-L145)在询问换怪前给对手常见属性与战斗风格提示；`battle_factory.c` 有 `sRequiredMoveCounts` 风格阈值。 | 当前项目有 `factoryBattleStyle.ts` 和训练家模板，但玩家是否在准确时点看见提示仍需运行验收。 |

以后提出对战工厂机制时，先按 [参考索引](../对战工厂_参考索引.md) 核对参考数据和当前代码，再写清楚“参考实现”“项目已有规则”“用户定稿”“新提案”四种来源。旧迁移记录可能落后于当前代码，例如早期清单仍称只移植少量 set，而当前 `factoryReferenceSets.ts` 已列出 110–881；但 `factoryBattle.ts` 当前把 `useReferenceSetPool` 设为 `false`，数据存在不代表运行中采用固定池。实际完成情况以本轮代码和运行证据为准。
