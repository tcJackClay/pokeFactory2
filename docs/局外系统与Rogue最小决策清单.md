# 局外系统与 Rogue 最小决策清单

本清单用于把《宝可梦对战工厂_项目设计框架_v1.md》中的产品方向转成可验收规则，**所有备选项均未获用户批准**。参考实现只按《对战工厂_参考索引.md》定位本地 `reference/pokeemerald-expansion` 的工厂固定池与抽样代码；已核对的七战、换怪和 BP 路径见《docs/对战工厂原型核对.md》。初遇伙伴、培育、图鉴、事件、每日挑战、研究任务和 Rogue 是 PokeFactory2 的扩展，不能称为原型规则。

## 已有边界

| 事项 | 当前依据与效力 | 对本清单的约束 |
| --- | --- | --- |
| Classic 核心 | 用户定稿见《docs/公开版规则定稿.md》；参考索引指向 `src/battle_factory.c` 的固定池与 `GenerateInitialRentalMons` | 六选三租借、非组末胜后可选换一只、第七胜结算；Classic 不进入奖励卡，局外伙伴和培育成品不带入工厂。 |
| BP | 用户定稿见《docs/公开版规则定稿.md》 | 工厂单打整组七胜后按参考表发 BP，败退 0，击败工厂首领加 10，上限 9999。框架 §6.2 的逐胜、失败保底、图鉴与事件发币是早期建议，不能直接实施为 BP。 |
| 公开版范围 | 用户要求完整设计框架后公开发布；商店商品暂缓定稿 | 下列系统需要确定可玩的闭环和验收边界；商品价格、局内消耗与新增 BP 来源不能凭线框示例定数值。 |

## 按玩家流程排列的最小决策

优先级表示规则决策的依赖顺序，不代表现在批准了备选项。每项先定玩家可见结果，再由技术任务实现。

| 优先级与玩家节点 | 已明确的方向 | 尚未定稿的最小选择与可溯源备选规则 | BP 与公平性影响 |
| --- | --- | --- | --- |
| P0 · 初次进入：初遇伙伴 | 框架 §3.1 明确初始事件偶遇一只宝可梦，它是局外长期锚点，**不进入工厂租借队**；§3.2 称它不是传统御三家选择。 | **取得方式与对象**：A. 固定物种、固定事件；B. 从限定遭遇池抽取。两者都符合“偶遇”，但物种表、能否重选、是否可丢失须定。§20.3 的“皮卡丘”只是线框示例，不是定稿物种。 | 若伙伴被允许影响租借候选、对战属性或首领难度，就越过 §4.1 的租借公平边界；先保持局外身份，任何局内作用另审。 |
| P0 · 进入工厂：模式选择 | 框架 §4.5 建议 Classic 与 Rogue 并存，§14.4 列为路线图；用户只定 Classic 不进奖励卡。 | **Rogue 最小边界**：A. 复用七战、六选三和固定池，只增加奖励卡；B. 另立 Rogue 规则集。A 最接近现有奖励页和 §4.5，仍需定奖励卡时点、可选项、换怪顺序、失败路径；B 须先给队伍规模、组长、首领、奖励与退出规则。详见《docs/tasks/模式区分/design.md》。 | Rogue 若能使用 BP 重抽、购物或将养成队带入，会使两模式的成绩与 BP 收益不可直接比较；须先定独立纪录和经济边界。 |
| P1 · 战斗中与战后：图鉴 Seen | 框架 §8.1–8.2 明确 Seen 表示在工厂或事件中见过，工厂首次遭遇可登记；§5.3 强调局外成长不直接碾压对战。 | **记录时点与粒度**：A. 出现在玩家可见的租借候选或敌方战场时记 Seen；B. 仅实际参战/事件演出后记 Seen。需确定物种、形态分别计数及重复遭遇去重。不得把未展示的固定池数据自动登记。 | §8.3 的图鉴阶段代币属框架设想；若补发 BP，就新增原型以外的 BP 来源，影响经济和排行榜，须单独批准。 |
| P1 · 回基地：图鉴 Owned / Forms | 框架 §8.1 明确 Owned 是正式持有过、Forms 是形态记录；§8.2 列培育产出、事件赠予、首领解锁为来源。 | **持有语义**：A. 取得后永久登记，失去实体仍保留历史 Owned；B. 只统计当前收藏池持有。需定蛋孵化与事件赠予的入册时点，以及特殊形态按物种还是独立条目显示。 | 如果 Owned/Forms 进度解锁战斗优势或发 BP，需明确不同模式是否共用，避免局外累积削弱 Classic 的租借策略。 |
| P1 · 回基地：培育可玩闭环 | 框架 §7.2 的“双槽、相容度、挑战次数或局外时间推进、孵化入收藏池”**标题明写 v1 建议**；§7.4 明确不应让培育产物直接进入工厂。 | **最少需定**：① 入驻来源：收藏池、初遇伙伴或事件取得者哪些可入驻；② 相容与产蛋：采用何种可解释规则，是否允许无效组合；③ 进度：按完成挑战次数或真实时间；④ 蛋如何领取、孵化、占位与取消。备选 A. 挑战次数推进，符合 §7.2 且易离线核验；B. 局外时间推进，符合 §7.2 但要处理改系统时间与离线恢复。未定具体阈值、继承、物种池。 | 培育产物仅入收藏池是公平边界。若孵化加速要花 BP，价格和是否影响每日挑战进度仍属商店待决；若培育成品参战则与工厂固定租借池冲突。 |
| P1 · 回基地：首批事件 | 框架 §9.1 明确与存档进度绑定、优先奖励内容访问权；§9.2–9.4 的触发维度、事件类型和“首胜解锁基地/3 次挑战解锁培育/Seen 30 解锁终端”等写作“建议”“可落地”，不是已批准阈值。 | **先定一条完整事件线**：A. 完成首个七胜后开放基地来客事件（沿用 §9.4 候选）；B. 从初遇伙伴的一次基地对话开始（沿用 §3.2、§9.3）。须给触发、展示、选择、奖励、完成标记、重复进入行为；其他事件随后配置。 | “天气赛、属性限定赛”等 §9.3 工厂异变会改变 Classic 赛制，应仅作为独立挑战或经批准的 Rogue 规则，不能暗改标准 Classic；事件 BP 奖励未定。 |
| P2 · 再次挑战：每日挑战 | 框架 §10.1 标为“推荐补充”，提出每日固定种子、同租借池和首领、排行榜/分享；尚无日期边界、模式、完整随机流和排行信任规则。 | **首版范围**：A. 本地每日同种子挑战，只记录个人成绩，不宣称跨玩家公平；B. 跨玩家统一规则与排行榜。B 需先固定日期时区、游戏版本、模式、随机调用顺序、作弊与提交校验。种子仅固定租借池不足以保证同局。 | 每日额外 BP 会增加原型外产出；排行榜若允许 BP 购买重抽或局外增益，会使成绩不可比。可先选择无额外 BP、独立纪录的范围，仍需用户确认。 |
| P2 · 长线回访：研究任务 | 框架 §10.2 标为“推荐补充”，仅举出“不同属性完成一组”“一组内换怪不超过一次”“异常状态击败五只”等例子；没有任务周期或奖励。 | **首版范围**：A. 不限时的生涯研究任务；B. 每日/每周刷新任务。需定统计事件、失败是否保留、Classic/Rogue 归属、领取次数与奖励。A 规则较少；B 另需时区、刷新及离线规则。 | 任务 BP 奖励属于新发放渠道；模式混算和可重复领取会改变经济与竞争公平。应先确定奖励是否仅为收藏/内容访问权。 |

## 需要先处理的规则冲突

1. 框架 §1.3 的“失败也有成长”可由 Seen、事件记录、培育进度承接；§6.2 的失败保底代币与用户已定的**败退 0 BP**直接冲突。不能把失败成长自动解释成 BP。
2. 框架 §6.2 的逐胜、图鉴、事件代币与已定参考工厂单打 BP 发放条件冲突。若未来要额外货币或其他 BP 来源，必须另列经济规则；不能静默复活旧逐场代币。
3. 框架 §4.2 的“赛后奖励/事件”是一般流程，§4.5 把奖励卡放在 Rogue 建议；用户已定 Classic 只换怪或组末结算。事件如改写 Classic 对局，也必须先单独定义模式边界。
4. 框架 §7.4 与参考索引所指 `src/battle_factory.c` 固定池租借逻辑共同限定：局外培育个体、初遇伙伴、事件赠予个体不得直接替代 Classic 租借候选。参考实现没有这些局外系统，不能从参考代码推断其详细规则。
5. 框架中的 §9.4 数字阈值、§20 界面演示数值、§21 初始字段值均是设计示例或草案，不能作为测试预期。先批准规则表，再写验收数值。

## 决策完成的最低证据

每个决定应记录来源、适用模式、玩家可见行为、存档字段、可重复/重置条件与一条可试玩的成功和失败路径。涉及 BP 的决定另写产出或消耗来源、次数上限、幂等条件；涉及排行的决定另写版本、种子、时区及可使用的局外加成。商店商品与价格仍按《docs/tasks/基地商店/design.md》保持待决，不在本清单中批准。
