# 九世代离线资料覆盖审查

结论：离线盘点脚本经局部修复后通过静态审查。当前未激活固定 PokeAPI 版本，报告中的全部固定 JSON 覆盖均为 0；因此不能据此宣布九池资料已具备离线发布条件。

- 分母与运行时一致：`getRandomPokemonIdentifier()` 从九代编号区间和 `DIRECT_SPECIAL_FORMS` 选取，索引逐代数量等于区间基础物种加直接形态，再剔除工厂禁用的未知图腾。脚本得到 1075 个候选；本地 Frontier chunk 共 772 个 set，剔除未知图腾后为 771。训练家参考 set 的物种均包含在对应索引世代中。参考招式只作为已知下界，未把第 4–9 代的 0 当作无需招式。
- 固定版本判定沿用 Go 内容服务的 `var/current.json` 优先、`var/pokeapi/current.json` 后备和 `var/pokeapi/versions/<version>/manifest.json` 路径。脚本只读取该版本清单中的对象，检查对象路径在版本目录内、键、大小、SHA256 与 JSON；不读取 `var/pokeapi/runtime` 作为覆盖。当前两处指针均缺失，重新运行脚本与已提交 JSON 报告逐字段一致。
- 原脚本在哈希正确但宝可梦正文缺 `moves` 等依赖字段时，会把招式全集误报为空；已补依赖字段校验和宝可梦正文实际 `species.url` 的物种键核查。无效正文现在列入问题和缺键；manifest `entries` 为数组也判无效。新增针对上述情形的测试。
- 图像按每个候选的 `pokemonId` 查 `report.json` 中前面、背面、官方画的原路径及文件存在性；同一物种形态按候选分别计数。Go 服务对缺背面/官方画可回退前面图，但脚本未把回退算作原素材覆盖。第 6 代背面 73/79、第 9 代背面 8/143，需要画面验收。
- `node --check` 两个脚本、4 项定向测试、报告再生成对比和本次文件的 `git diff --check` 通过。未联网、未同步资料、未运行游戏。完整招式/特性/形态/进化链分母须在固定版本准备后再次推导，并以关闭上游的九池实际请求验证。
