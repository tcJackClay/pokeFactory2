# 九世代租借池性能记录实施

在开发模式加入 `[rental-perf]` 结构化控制台记录，用 `performance.now()` 计时，不改变随机抽样、资料加工、缓存键或战斗流程。正式构建不输出这些记录；新记录只包含世代、阶段、槽位、尝试数、耗时、请求类别、响应状态、内容来源及长度，不包含存档、宝可梦编号、训练家或请求 URL。

- BOOT 预取开始及完成、点击开始挑战、六卡实际解除交互锁定分别计时。预取与进入基地仍并行，卡片耗时单独从点击开始计算。
- BOOT 日志在 effect 保持有效后发送，StrictMode 的首次模拟卸载不会形成重复开始/结束记录；预取请求仍按原时点启动。
- 租借索引读取、六个成员逐槽耗时、每槽候选尝试数及最终成员资料加工耗时分别记录。已有六只顺序处理和完整资料请求保持原样。
- 敌队预取开始/完成、确认时使用已完成预取、等待预取或重新生成的来源分别记录；确认到首个实际启用战斗指令的耗时以按钮所在组件提交后的状态为终点。训练家入场到人工继续的耗时另列，便于从确认总耗时中拆分。
- 在索引与同源 PokeAPI JSON 响应处记录 `X-Content-Store` 的 `VERSION`、`RUNTIME`、`UPSTREAM` 或 `UNKNOWN`，只按索引、宝可梦、物种、特性、招式归类，不打印 URL 与 ID。记录名为 `content-response-in-capture-window`：它包含采集时间窗内完成的相关端点响应，也可能包含同时打开图鉴等功能的请求；不能直接当作租借任务独占请求数。`Content-Length` 仅记录响应头值，缺失时为 `null`，不等于实际传输字节数。确认租借失败会清除确认计时，避免后续其他战斗被算入本次确认。
