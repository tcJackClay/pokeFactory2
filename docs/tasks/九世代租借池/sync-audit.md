# 工厂有限闭包同步审计

结论：首切片的有限闭包和假上游验证可接受；工厂同步仅可作为隔离准备流程，不能作为发布激活流程。本次审计已加固隔离路径、并发版本目录和激活门禁。未进行九代大同步、真实网络同步或游戏运行验收。

## 核对结果

- `factorySeeds` 以工厂索引中的候选为 `pokemon` 种子，验证 1–1025 基准 ID 与 `specialForms.ts` 中的直接形态，加入参考 set 固定招式；排除物种 201。与运行时九代候选索引口径一致。
- `FactoryClosure` 仅从 `pokemon` 响应发现 `species`、`ability`、`move` 正向键。物种、特性和招式响应不再扩展；键排序去重，清单逐条记录父键。外域 URL、必需字段缺失、HTTP 错误会导致失败。
- 键数、累计字节、期限和单响应 64 MiB 上限在存储层执行。工厂命令的键数、字节预算现在包含 CSV，期限跨 PokeAPI 与 CSV。失败不会改活动指针；已准备的另一命名空间版本可能保留，重试须使用新版本号或人工核查后清理。
- `-full` 保留原有递归抓取和激活路径。`-factory`、`-factory-sample` 只准备，不激活；工厂模式拒绝当前目录或仓库共享 `var` 及其子目录，包括 `./var`、绝对路径和可解析的符号链接。已有版本和并发发布锁会阻止目录覆盖；目录改名失败不再降级为拷贝覆盖。

## 修复的问题

1. **P1，已修复：**`-factory` 原来在缺少独立闭包、对象哈希与 CSV 联动校验时直接调用 `ActivateRelease`。现在只准备版本，CLI 和实施文档明确说明不能用作发布命令。
2. **P1，已修复：**样本只比较 `-state` 字面值 `var`，路径别名可绕过；完整工厂模式也能写共享目录。现在按真实路径检查，并要求所有工厂任务使用隔离 state。
3. **P1，已修复：**Windows 改名失败时原代码回退到目标目录拷贝，且失败时删除目标，可能影响其他进程的同名版本。现在加跨进程保留锁并直接返回改名错误，不会拷贝或删除同名版本。
4. **P2，已修复：**工厂模式原上限只计 PokeAPI；CSV 不受累计字节和总期限约束。现在合并预算和期限。

## 尚未完成的发布门槛

- 完整九池版本的独立闭包、对象哈希、图片与 CSV 联动校验，以及关闭上游的端到端验收未执行。本审计不批准激活或公开发布。
- 进程异常退出可能留下 `.tmp` 目录或 `.publish.lock`。清理前须确认没有同步进程正在运行；当前没有自动垃圾回收。
- 本次目录锁只协调使用此版本同步器的进程；外部程序直接改写版本目录不在保护范围内。

## 静态验证

本地假上游测试覆盖有限闭包、父键、失败不激活、上限与版本目录隔离。`go test ./...` 与 `go vet ./...` 通过；没有运行游戏、联网或九代大同步。
