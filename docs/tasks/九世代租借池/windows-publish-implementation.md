# Windows 内容版本目录发布修复

目录发布改用 Windows `MoveFileExW` 无覆盖标志；同版本发布锁在整个重试期间保持。只对 Windows AccessDenied、SharingViolation、LockViolation 重试，累计退避窗口最多 30 秒，其他错误立即返回。每次失败记录序号、错误码、耗时、源/目标/锁的绝对路径与文件属性；若目标在重试中出现，立即停止，不覆盖、不合并、不删除目标。没有加入复制回退。

对象下载、JSON 发现、上限或 manifest 写入失败仍只清理本任务在指定 `versions` 目录下的暂存。完整 manifest 写入后若目录发布失败，保留该暂存，错误包含明确绝对路径、对象数、manifest 字节数与“未激活”；现有活动指针不变。受限手动重新发布入口及逐对象激活前审计尚未实现，保留的暂存不能直接视作可激活版本。

仅用本地假数据验证：746 个对象约 25 MiB 的目录正常发布；Windows 目录句柄短暂占用后恢复；持续占用在测试用短期限内失败并保留源目录；已有空/非空目标、外部目标在重试中出现和现存发布锁均拒绝覆盖；假上游在下载时创建目标后，完整 staging 与 manifest 留存且错误包含其绝对路径。`go test ./...` 与 `go vet ./...` 通过。未调用真实 PokeAPI，未清理或重跑旧第六代试验目录。

独立复审补充：Linux amd64/arm64 使用 `renameat2(RENAME_NOREPLACE)` 原子发布，目标即使是空目录也不会被替换；内核或文件系统不支持该操作时直接失败并保留完整暂存。其他非 Windows 平台仍明确拒绝目录发布。Windows 与 Linux 的 Go 测试、Go vet 已通过，Linux amd64 测试在 WSL 实际执行，arm64 仅交叉编译。暂存清理增加解析后目录边界校验，发布成功后不再试图清理已移动的暂存路径。

真实第六代隔离重跑下载了 746 个对象、25,476,461 字节，目录发布在 30 秒重试期内持续 AccessDenied。进程退出后，原暂存目录和逐对象哈希核验过的复制暂存仍无法手动重命名；同目录小目录可重命名，而这两个暂存内部的 `objects` 子目录和 manifest 可重命名。没有激活版本，也没有删除旧暂存。这组证据说明重试不能消除该次阻断；它尚不能区分根目录句柄占用、访问控制或安全软件等原因。当前 Vite 服务正在运行，其文件监视是待排查线索，未证实为原因。下一次真实同步前，应先查占用该暂存根目录的进程句柄并在服务停止或将隔离状态移出监视范围后做同目录重命名探针；不要重复下载或删除完整暂存来试探。

后续停止本轮试玩启动的 Vite 与 Go 服务后，原暂存及其复制暂存都能在同一目录改名并改回。原暂存 manifest 的版本和 746 个对象数复核通过，此前对复制暂存逐对象 SHA-256 核验为 0 处不符；将原暂存无覆盖地改名为隔离版本 `output/factory-gen6-trial2-20260926/pokeapi/versions/gen6-trial2-20260926`。`current.json` 仍不存在，该第六代试验版本**未激活**。这把服务运行时的目录句柄占用列为强线索，尚未单独锁定具体进程。Vite 已加入 `**/output/**` 监视忽略。

新配置下重启 Vite 和 Go 服务后，对同一隔离版本的逐对象核验复制目录再次做“改名→改回”探针，两次均成功。这样已覆盖“服务运行、目录约 25 MiB”的原阻断条件；该试验版本仍未激活，也未用真实同步命令重新下载。是否为 Vite 监视独自造成旧锁仍不能由此单独断言，但忽略 `output` 后目录发布所需的改名已可执行。
