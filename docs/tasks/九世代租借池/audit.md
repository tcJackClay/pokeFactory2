# 九世代租借池性能埋点审查

结论：计时与正式版隔离的静态审查通过；此埋点只足以辅助定位，尚不足以单独完成 `performance-plan.md` 的请求数、六张图可见和九代三次中位数验收。未运行游戏或提交。

- `[rental-perf]` 受 `import.meta.env.DEV` 控制；正式构建产物中未检出该日志标记。新日志只含世代、关卡、槽位、尝试数、耗时、请求类别、响应状态、来源及响应头长度，不写存档、物种 ID、训练家 ID 或 URL。租借抽样、随机调用、缓存键、资料请求及战斗动作没有因计时而改序；确认时敌队缓存分支仍沿用原条件。
- `X-Content-Store` 从实际 `Response` 读取，分类正则区分索引、pokemon、pokemon-species、ability、move。审查发现全局采集计数也会包含同期图鉴等请求，已把事件明确改名为 `content-response-in-capture-window`；它是**时间窗聚合**，不能当成租借独占请求数或必需 JSON 覆盖率。`Content-Length` 缺失现记为 `null`，该响应头也不代表实际传输字节数。
- BOOT effect 的日志现在忽略 StrictMode 首次模拟卸载与真实卸载后的异步完成；预取请求仍立即启动。确认租借失败会清除待计时状态，避免后来其他战斗误报确认耗时。租借和敌队采集均在 `finally` 释放；首个可操作命令在战斗面板已提交、敌人存在、玩家回合且按钮 fieldset 解除禁用后记录。
- 仍缺“六卡可操作→六张图可见”的程序内时点；可由 player 的浏览器资源瀑布人工补证，若需自动算三次中位数应另补图像完成埋点。网络时间窗无法排除并发图鉴请求，玩家验收应保持该窗口无其他资料操作，或另以浏览器逐请求记录核对。尚未取得九代冷/热三次原始样本，不得据此宣称性能达标。
- `npm run lint`、`npm test`（136 项）、`npm run build`、`git diff --check` 通过。
