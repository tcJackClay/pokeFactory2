# 世代设置实施计划

## 现状与目标

- `src/constants.ts` 已定义第一至第九世代及对应地区、编号范围。`usePokeFactoryGame.ts` 中 `selectedGens` 目前是多选数组，无存档时默认九代全选；`src/services/saveManager.ts` 当前未正式交付的 v9 `settings.selectedGens` 也容许多值。此实现与用户新定的九个互斥池规则冲突，不能直接只加设置按钮。
- `SettingsScreen.tsx` 当前有语言、存档、通知、版权与开发选项，没有世代控件；`StartScreen.tsx` 的挑战主按钮直接开始或继续，也没有世代选择。本任务只在设置内提供入口，开始挑战时不增加选择步骤。
- 当前初始租借可从多个世代混合随机；`factoryBattle.ts` 的 `useReferenceSetPool=false` 是为九代覆盖。原型固定 Frontier set 只有 110–881 编号，不能覆盖九个独立池。界面应把此机制称为“扩展世代随机池”，不得称“原型固定池已对齐”。原型 Classic 固定池切换依赖《原型租借池对齐实施计划》的模式边界任务。

## 实施

1. 在 `SettingsScreen.tsx` 增加“出场世代”区块，九个按钮显示世代和地区，采用单选组或原生 radio 语义。文案明确“九选一”“下一次新挑战生效”。手机单列/双列自动排布，保持触控目标和滚动。
2. 最短路径是保留 `viewModel` 和工厂流程使用的 `selectedGens: number[]` 接口，但新版本始终只存一个合法 ID，例如 `[1]` 至 `[9]`；设置点击直接替换为 `[id]`，绝不追加。以 `GENERATIONS` 为合法值表，默认第一世代 `[1]`。在初始化、导入和保存边界约束单元素。当前 v9 尚未正式交付，建议将发布目标 schema 提升到 v10，旧多选数据不迁移；不兼容时明确提示或重置为默认池。刷新与导入/导出后的选择必须一致。若实施时改为单值字段，须同步改所有消费者与预取键，不允许同时保留两套含义。
3. 以“下一次新挑战生效”为规则。设置页在有暂停/可继续的工厂局时锁定世代控件并说明要先完成或结束当前挑战；继续按钮沿用该局世代，不允许中途改变已生成的租借队伍、敌方队伍和奖励。开始新局前可修改。检查所有局内进入设置路径，同样锁定。若存在可从运行局间接修改的入口，须在运行数据中保存单一世代快照并以其生成后续对手，不能只依赖当前设置值。
4. 修改前后处理 `useFactoryFlow.ts` 的租借与敌方预取：缓存键虽已包含 `selectedGens`，仍需在设置变化时取消或失效旧世代进行中的结果，且不得让旧请求回写当前缓存。检查 `buildRentalPrefetchKey`、`buildEnemyPrefetchKey`、请求 token 与 `startGame` 消费路径。空/非法世代不得进入 `getRandomPokemonIdentifier`；服务数据缺失时显示错误而非无限等待。

涉及文件：`SettingsScreen.tsx`、`view-model/state.ts`、`view-model/setters.ts`、`usePokeFactoryGame.ts`、`saveManager.ts`、`useFactoryFlow.ts`、相关测试。`StartScreen.tsx` 仅在必要时补充指向设置的简短提示，不增加挑战前选择表单。

## 验收

- 静态：检查九项映射、单选语义与文案；选中第二项时第一项立即取消；任一时刻恰有一个合法 ID；空、非法或旧多选 v9 数据依新版本策略提示/重置；保存、刷新、导出导入后不变。验证有可继续挑战时控件锁定、新局后可再调整；验证旧预取请求不会覆盖新世代缓存。运行类型检查、构建与定向测试。
- 手机浏览器：在 `390×844`、`320×568` 竖屏和 `844×390` 横屏打开设置，逐项单选、滚动、返回基地、刷新并复查；选第九世代开新挑战，六张租借卡及战斗对手均不出现其他世代的随机物种；结束局后切换第一世代再开局并核对来源；暂停可继续挑战时尝试改世代，应看到锁定说明且继续局内容不变。记录实际截图、请求错误和加载时间；模拟视口后再以实体手机复核触控。
