# 基地商店设计草案

本文依据《宝可梦对战工厂_项目设计框架_v1.md》§4.4–4.5、§5.2–5.3、§6、§14.1–14.2、§17.4、§20.6，以及《公开版需求矩阵.md》“BP 经济”“商店与解锁”两行。用户已决定**先完成基地钱包与组末 BP 结算，商品稍后再定**。下表两个商品、价格及解锁条件均为**未批准的旧提案，不进入当前实现**；其中价格以旧代币节奏假设写成，须在 BP 经济下重新设计，不能据此实现。

## 已有钱包基础与本草案范围（2026-10-13 校正）

- 前六战不发 BP；第七战获胜完成整组后，按参考工厂单打表将 BP 入持久基地钱包，实际击败首领额外 10 BP，并将本组未用兑换券按 1 券 = 1 BP 计入同一次结算后清券；合并受 9999 上限约束。败退 0 BP，剩券清零不折算。玩家在基地能看到余额。
- 组末结算、败退、继续挑战和刷新后，余额与组末到账结果一致；同一组不重复入账。
- 不要求兼容过往存档；可重置或拒绝旧档，但须明确提示且不能把旧代币转换为 BP。
- 基地 BP 商品、购买、扣 BP、展示位或消费效果仍待商品定稿。本草案不限制已经合入的工厂交换商店：后者在每组第 3、6 胜后使用兑换券购买六件货架中的合格商品，与基地 BP 消费分开。

## 已确定的产品边界

- BP 是局外长期货币，本文件所说的基地商店用 BP。单线工厂内已经有使用兑换券的交换商店。工厂租借队不由局外永久收藏队替代，局外购买不直接给予永久战斗数值优势。
- 商店面向非繁殖解锁项、便利功能和外观收藏；商品目录应配置化。框架提出低价常购、中价成长、高价收藏三个层次，但未给出具体商品、价格或上架条件。用户 2026-10-13 明确不创建生蛋系统，依赖产蛋/孵化/双槽繁殖的商品与任务移除，不是延期。
- 用户最新定稿：**整组七战获胜后按参考工厂单打表发放 BP；前两组各 3 BP，之后按完整表，实际击败工厂首领额外 10 BP；败退 0 BP。组末余券另按 1:1 折 BP，钱包上限 9999。**该组末规则已实现，不能再按旧逐场代币收入给商品定价。
- 本轮基地应让玩家看到当前钱包余额；商品定稿并进入后续实现时，还应展示可消费内容和购买后的实际效果。没有效果的按钮或只扣币的占位商品不符合完整循环。

## 尚未定稿的规则

| 问题 | 需要确定的内容 | 影响 |
| --- | --- | --- |
| 经济数值 | 钱包上限 9999 和工厂组末收入已定；生涯统计口径、图鉴/事件是否给 BP、商品价格与价格成长仍待定 | 能否负担首件商品、失败后是否仍有可见成长、长期通胀 |
| 商品生效点 | 如批准情报商品，其在单线工厂“下一场”的作用点、回基地/结算/读档后的保留与消耗 | 战前提示、消耗时机、重复领取 |
| 对手风格分类 | 从什么已知敌队数据推导标签，以及无明显倾向时如何呈现 | 信息准确性与策略价值 |
| 商品解锁 | 商店入口默认开放还是由剧情开放；图鉴展示位的门槛是否采用本提案 | 新存档引导和基地高亮 |
| 交易边界 | 余额不足、重复购买、购买中断、超出持有上限时的处理；旧档可重置或拒绝并须提示 | 钱包与商品状态一致性 |
| 与工厂商店的关系 | 已定单线工厂、不重抽；工厂购物只扣兑换券，基地购物才按获批商品扣 BP；若基地商品影响战前信息，须写明生效边界 | 避免混币扣款、付费恢复或永久战斗数值优势 |

## 当前钱包闭环

1. 玩家完成七战整组并获胜，在组结算页看到本组原型 BP、实际首领额外 BP 与余券折算；基地钱包增加一次，合并受 9999 上限约束且券清零。前六战及败退不发 BP，败退也不折券。
2. 玩家回到基地，看到与组结算一致的余额；刷新或重开游戏后余额仍在。
3. 玩家继续挑战，完成下一组后再次按参考单打表获得 BP；先前余额不会被局内临时状态覆盖。

## 商品提案若获批后的示例闭环（不是当前验收要求）

1. 玩家完成七战整组并获胜，在组结算页看到按现行规则结算的 BP（含余券折算），基地钱包增加一次；败退 0 BP。
2. 玩家返回基地，打开商店，看到余额、商品效果、价格、持有/解锁状态与购买结果。
3. 玩家购买情报券，在下一场战前看到可信的风格提示；使用后券数归零，再次到基地可重新购买。
4. 玩家获得首条 Owned 图鉴记录后购买图鉴展示位，选一只已拥有的宝可梦放在基地；重新打开游戏后仍可见。
5. 玩家继续挑战，获得新 BP 并再次消费。战斗中的数值胜负仍由租借队和局内决策决定。

## 当前钱包验收标准

- 手机竖屏 `320×568`、`390×844` 和横屏 `844×390` 下，基地钱包余额可读，不遮挡主操作。
- 前六战钱包 BP 不增加；整组第七战获胜后按参考单打表、实际首领奖励与余券折算恰好入账一次，受 9999 上限约束；败退 0 BP。组结算页与基地余额一致；刷新、返回基地、继续下一组和同版本导入导出后余额一致。
- 旧档可重置或拒绝导入，但须明确提示，不能把旧代币当 BP；不以商品或购买流程作为本轮通过条件。
- 实际试玩覆盖前六战、七战胜利、败退、继续下一组与刷新恢复，记录提交号、视口、存档起点、钱包前后值、画面与错误日志。

## 商店定稿后的验收标准

- 手机竖屏 `320×568` 和 `390×844` 下，商店入口、商品效果、余额、购买按钮、错误提示均可读可点；横屏 `844×390` 不遮挡购买确认。
- 整组七战获胜后钱包按现行组末 BP（含余券折算与上限）恰好入账一次，败退 0 BP；组结算页与基地余额一致。刷新、返回基地、继续下一组和同版本导入导出后余额及购买状态一致。
- 余额不足、重复购买永久商品、持有未使用情报券、无 Owned 记录等情况不会扣币，也不会产生无效物品；购买成功只扣一次。
- 情报券在有可信提示的战前生效一次，不泄露完整敌队；图鉴展示位只接受 Owned 条目，切换后可持久恢复。
- 商品规则定稿后再设计购买试玩路径；现有两类商品和旧价格均非验收要求。记录提交号、视口、存档起点、钱包前后值、商品状态、画面与错误日志。

商店验收标准在商品和未定规则经用户确认后才生效。当前阶段只按钱包验收标准推进，不把候选商品的价格或解锁条件写成公开版既定规则。
