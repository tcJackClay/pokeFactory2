## 1. 缺陷证据与最小范围建议

自然证据：`docs/tasks/自然长局基线/runtime.md`「产品缺陷：高速旋转将提速施加给对手」；`evidence/attempt-2/rapid-spin-target-observation.json`。

- actor 海星星 ID120 速度阶级 0→0，target 小拳石 ID74 速度 0→1，目标 HP28→24；原始记录为 `meta.category=damage-raise`，实际构造却 `appliesTo=target`。
- 这是真实自然抽取/出招后观察，无数值或招式注入。旧自然证据证明缺陷存在，修复后必须重新取证；不能推断原本败退一定会变成获胜。
- **建议一次串行切片完成**：高速旋转伤害后对自身的速度变化；解除自身已有束缚/寄生；清除本侧已有隐形岩/毒菱；共享伤害自强化目标识别的必要回归。双方使用同一规则，日志必须随真实受益者生成。
- 不新增撒菱、黏黏网、钢阵等当前不存在的场地系统，不扩大成全招式重写。它们的源语义记在下文，缺失仍是公开版招式覆盖遗留，不能宣称“全部高速旋转互动已完成”。

## 3. 可实施规则

### R1. 提速与伤后时序

正常命中并对目标有效后，使用者速度阶级 +1；目标速度不因此改变。伤害和清除不要求使用者速度尚可提升；使用者已+6时仍正常造成伤害、清除，速度保持+6。自身能力修正仍沿统一阶级规则，例如单纯倍增、唱反调反转，不能硬写到对手或绕过阶段上限。

依据：S5425–5439明确 `MOVE_EFFECT_AFFECTS_USER`、`STAT_SPEED,1`；C11577–11620按使用者选目标并处理唱反调/单纯，C11838–11843约束阶级。这不是依赖额外随机10%/100%骰子的概率奖励；源 `.secondaryEffectChance=0` 由专用脚本实现。源高速旋转也没有 `.sheerForceBoost` 标志，不能因通用伤害自强化分类把它的提速/清除当作强行可抑制的普通次效果。

### R2. 命中、保护、免疫、替身和击倒

| 场景 | 伤害 | 自身速度与清除 |
| --- | --- | --- |
| 普通有效命中 | 正常结算 | 先完成本次伤害，再清除并尝试自身+1 |
| 普通落空、无法行动、保护挡住 | 不产生有效伤害 | 不发生；不能看到挥招动画就提速 |
| 实际属性免疫（如一般攻击幽灵且没有有效破免条件） | 无效果 | 不发生；S5426显式检查 `MOVE_RESULT_DOESNT_AFFECT_FOE` |
| 打到目标替身，替身尚存或被打破 | 伤害由替身承担 | 仍清除并提升使用者，不要求目标本体掉HP |
| 击倒目标，包括该方最后一只 | 正常伤害/倒下 | 清除和速度步骤在S5437的目标倒下处理之前；不能因目标HP=0跳过整个自身效果 |
| 速度已+6 | 正常结算 | 清除正常，速度保持上限，无虚假的继续提升 |

依据：S3499–3519及3554–3563的命中失败出口；C2980–3016将自身效果绑定施招者、替身门禁不拦 `AFFECTS_USER`；S5427–5437专门步骤。C3855–3889确定清除检查 `MOVE_RESULT_NO_EFFECT`；清除自身对象时存活检查针对使用者，不因目标倒下取消。

高速旋转是接触攻击；现有接触反伤等仍按统一战斗流程执行。固定脚本在最后 `moveendall` 才进入后续事件，因此不能先把使用者在接触反伤中倒下作为理由删掉前面的合法伤后步骤；也不能给随后换入的成员转移这次速度变化。若本项目顺序与固定源有差异，应在本任务 plan 明确并验证。

### R3. 解缠绕、寄生和本侧清场

一次有效命中清除**全部符合项**，不是每次只能清除一项。源 C13696–13765虽写成 `else if`，每清一项均 `BattleScriptPushCursor` 返回同一清除指令继续，最后无项目才前进。

| 对象 | 固定源行为 | 本项目切片边界 |
| --- | --- | --- |
| 使用者持续束缚 | 清 `STATUS2_WRAPPED`，解除缠绕等持续伤害束缚 | 对应现有 `trapped`（由 DAMAGING_TRAP产生），清持续伤害与禁止普通换人的束缚 |
| 使用者寄生种子 | 清寄生位及来源位 | 清现有 `seeded` 和其关联来源；本回合末不再扣寄生HP/给对方回血 |
| 使用者一方撒菱 | 清侧标志，层数归0 | 当前未有对应持久场地状态，本次不新增；标为未覆盖 |
| 使用者一方毒菱 | 清侧标志，层数全部归0 | 当前已有，必须清；不是减一层 |
| 使用者一方黏黏网 | 清侧标志，数量归0 | 当前未有对应持久场地状态，本次不新增；标为未覆盖 |
| 使用者一方隐形岩 | 清侧标志，数量归0 | 当前已有，必须清 |
| 使用者一方钢阵 STEELSURGE | 清侧标志，数量归0 | 当前无对应状态，本次不新增；标为未覆盖 |

**不清除**对方场地陷阱、对方寄生/束缚、自身非易失异常、己方反射壁/光墙/顺风，以及天气/全场场地。源没有清 `STATUS2_ESCAPE_PREVENTION` 或扎根等，所以不能把“解束缚”泛化成所有禁止换人效果。现有中毒不会因为清掉毒菱而痊愈；下一名己方正常换入才不再踩已清陷阱。

清除与提速彼此独立：无可清项目仍可提速；速度到顶仍可清全部项目；清除不吞第二次PP。敌方使用时镜像作用于敌方自身和敌方一侧。

## 5. 同类目标错误的代表与回归边界

下列是固定源给出的**自身强化攻击**，当前没有相同名称的专用override，可能落入同一通用目标错误；只是代表，不要求扩写全招式设计。真实上线适用性须由architect沿输入数据核对。

| 招式 | 固定普通源 | 受益者 / 注意 |
| --- | --- | --- |
| 蓄能焰袭 flame-charge | B8575起；S2841–2843 | 自身速度+1，普通次效果100%；有sheerForceBoost，不能照搬高速旋转专用非抑制语义 |
| 增强拳 power-up-punch | B10680起；S5564–5566 | 自身攻击+1，100%；同样有sheerForceBoost |
| 充电光束 charge-beam | B7953起；S1975起 | 自身特攻+1，70%；不可因受益者改user顺手改成必发或绕过强行 |
| 对照：虚张声势 swagger | B3716起；S5296–5317 | 对手攻击+2并尝试混乱；它是对敌变化技，不能因change>0改成自身 |
| 对照：吹捧 flatter | B4660起；S5973起 | 对手特攻+1并尝试混乱，同理不能按正数一律归自身 |

“自身效果”不等于“主效果/不可抑制”：现有 `lib/battleResolution.ts:719–737` 区分强行、鳞粉等门禁。共用builder修复须保留概率、同组判定与真正的次效果语义；不以所有正向变化=user或所有user=isPrimary的一行推断替代固定规则。

## 6. 建议验收结果（产品层）

1. 重建自然证据输入，真实操作高速旋转后 actor速度0→1、target速度不变；日志名字与状态一致，目标仍受到伤害。双方各一例。
2. 落空、保护、实际幽灵免疫分别验证不提速、不清除，扣PP仍按正常使用规则。
3. 替身未破/打破分别验证只扣替身HP，同时使用者提速和清除；击倒普通目标/最后目标不漏自身步骤，也不将提升写给换入成员。
4. 让使用者同时有束缚、寄生、本侧岩钉及两层毒菱，速度+6；一次命中全部清除，速度仍+6，对侧陷阱和无关异常不变。本回合末无已清束缚/寄生伤害，下一次己方入场不踩已清陷阱。
5. 无束缚/寄生/陷阱仍正常伤害+提速。只有对侧陷阱时对侧保留。
6. 共用解析回归：选一项概率自身强化攻击，正向对敌状态技虚张声势/吹捧，和一个既有显式override；不得误改目标、概率或重复提升。不要用受控通过宣称自然已抽到全部代表。
7. 在新提交重做一次自然短链确认原错误不再出现；七战/商店长局证据另行继续，不能由上述受控场景代替。
