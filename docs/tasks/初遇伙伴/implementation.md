# 初遇伙伴实施记录

- 存档升至 v11，`progress.companionSpeciesId` 只允许六个候选 ID 或 `null`。旧 v10 由现有旧版备份/清除入口拦截，不迁移或默认指定皮卡丘。同版缺失或非法 ID 按损坏存档保护，不能自动保存覆盖原文。
- 六只候选由 `companionCandidates.ts` 单一配置提供，顺序固定，与工厂世代设置无关。新档启动后先进入初遇页面，一次列出六只；确认前选择只在页面本地变化，未选时不能确认。
- 确认会同步校验并写入存档，读回核对后才切换到基地。写入失败保留页面与选择，可重试；相同 ID 重复确认幂等，已绑定 ID 不能改选。自动保存合并已有绑定，避免旧闭包把 ID 写回 `null`。
- 基地从存档读取伙伴 ID 和本地化名称；皮卡丘沿用已有双帧图，其余五只走同源官方图路径并回退到同源普通图。初遇伙伴不参与租借队、敌队、战斗或 BP 运算。
- 静态测试覆盖候选白名单、未确认、非法同版存档、失败后重试、重复确认、旧草稿自动保存、同版序列化和旧 v10 拦截。资源报告与本地文件均包含六只的官方图和普通图。手机视口、图像响应、刷新及实际挑战隔离仍待 player 在集成后验收。
- 隔离工作树静态门禁：`npm run lint`、`npm test`（137 项）、`npm run build`、`go test ./internal/assets` 通过；未运行浏览器。
