# 初遇伙伴运行验收准备

依据 [设计核对](design.md) 和 [实施计划](plan.md) 制定。此文件仅列实际试玩步骤与取证方法；程序员仍在隔离工作树实施，尚未打开主目录游戏、创建浏览器存档或作通过判断。

## 样本与证据

- 使用全新 Chrome 浏览器上下文和未使用过的隔离 loopback 来源，例如 `127.0.0.90:4300` 起；每种世代与故障样本各用不同上下文。先核实来源可达且该上下文没有存档。绝不访问或清除用户 `127.0.0.1:4300` 的存档，也不复用此前九池验收的 `.80`–`.89` 来源。
- 在代码合入并收到开始通知后，记录 Git 提交、工作树状态、页面构建版本与测试起止时间。若出现 Vite 热更新、服务重启或接口异常，标记受影响样本无效，待稳定后用新上下文重测。
- 每个关键步骤保存 320×568、390×844 或 844×390 截图、当前页面文字与可操作按钮、存档版本及 `progress.companionSpeciesId` 前后值、六候选 ID、当前 `selectedGens`、浏览器异常和失败请求。只读检查保存值；只有专设故障注入样本才拦截写入。
- 证据放入 `docs/tasks/初遇伙伴/evidence/`；结果表至少包含 `origin`、`viewport`、`build`、`step`、`selectedGens`、`candidateIds`、`selectedCandidateId`、`savedCompanionId`、`imageStatus`、`consoleErrors`、`httpErrors`、`screenshot`。运行后另写 `runtime.md`，严格区分真机、模拟视口、正常 UI 路径、故障注入与未覆盖范围。

## 主流程

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 新档首屏 | 等启动完成，滚动初遇页面，从页面读取六个候选的名称、物种 ID、图像状态和选中状态。 | 25 皮卡丘、133 伊布、175 波克比、447 利欧路、744 岩狗狗、921 布拨一次全展示；没有抽样、空卡、永久空图或“三只随机”旧文案；未确认时不能进入工厂。 |
| 确认前改选 | 依次点击六只，尤其先选皮卡丘、再改伊布、最后改利欧路；每次核对文字与视觉选中状态，读取存档字段。 | 同时仅一只被选中；确认前可以改，未确认的点击不会把候选 ID 绑定到存档；未选时确认不可用，确认说明指向当前存档绑定。 |
| 确认绑定 | 确认利欧路，观察返回基地；立即读取存档，再快速重复点击或尝试返回选择页。 | `progress.companionSpeciesId=447` 且仅完成一次；基地为利欧路的名称与实际图像，没有皮卡丘残图；无改选入口。 |
| 恢复 | 依次刷新、关闭并重新打开同一隔离来源；从设置通过 UI 导出同版本存档，再导入全新隔离上下文。 | 仍为 447，直接进入基地或原续玩路径，不重新弹初遇；导出 JSON 与导入后的字段一致，基地图像和名称一致。 |
| 其余候选 | 用独立新档分别确认另外五个 ID，至少截图基地展示并读回存档。 | 六个 ID 均可绑定，各自名称与图像对应；只有皮卡丘可以使用专属两帧图，其余五只不出现皮卡丘。 |

## 世代池独立与手机布局

在两个独立新档先进入初遇，核对完全相同、顺序稳定的六个伙伴 ID，并分别确认一只。进入基地后，再通过设置 UI 分别选择工厂第 1 代和第 9 代，随后正常开始 Classic：六张租借卡与首战敌队 ID 通过 `storage/data/factorySpeciesIndex.json` 核对，只属于当前选定世代；初遇伙伴不会因其身份直接加入三人租借队。第 9 代档选择一个非第 9 代伙伴，以直接验证伙伴与租借世代池独立。记录六卡与首战 READY；实际出招若未执行，要明确写为未验。正常 UI 样本不预写存档来改变流程顺序。

三个视口都走到选择页和基地：320×568 检查纵向滚动能触达六只及确认按钮；390×844 检查完整卡片和基地伙伴；844×390 检查横向不溢出、卡片不重叠，且滚动后仍可选中和确认。用触摸点击候选与确认，核对按钮不会被固定元素遮挡；分别截图页面顶部、底部、选中项和基地。图片网络请求必须成功，最终 `img.complete=true` 且 `naturalWidth>0`；若卡先于图出现，记录从名称出现到图像完成的时间。

## 异常路径

- 在单独的新档通过浏览器测试钩子让**第一次目标存档写入**失败，确认仍停留初遇、所选项保留且有可理解的重试反馈；解除故障后重试，存档只绑定一次。注入仅作用于该隔离上下文和目标写入，测试结束销毁上下文。
- 用隔离样本验证旧版本存档出现备份或清除提示；用字段缺失、非法 ID 与错误类型的同版本样本验证损坏存档保护，不自动指定皮卡丘，也不覆盖原文。此处只构造测试来源，不向用户或九池来源导入。
- 检查确认前刷新与离开页面后仍是未绑定状态；确认后刷新不会回到选择页。若浏览器脚本误点、素材延迟或开发热更新造成异常，单列为样本限制，不据此判定产品缺陷。

## 浏览器脚本思路

脚本按“新上下文 → 记录响应和异常 → 正常 UI 点击 → 截图与只读页面状态 → 只读存档快照”的顺序推进。只用页面上可见的语义名称定位按钮；状态断言同时读取可见文字和存档字段，避免仅凭定时等待。导出走设置按钮并保存下载原文，导入走设置的文件输入，在另一空白隔离上下文比对版本和伙伴 ID。候选图同时检查响应状态、`complete`、`naturalWidth` 和截图。不要调用游戏内部函数跳过初遇，也不要在正常样本中直接写 localStorage。脚本开始前确认服务与构建稳定，运行中记录 HMR 并停止污染样本。
