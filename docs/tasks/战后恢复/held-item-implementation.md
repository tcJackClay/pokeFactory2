# 工厂战间持有物返还实施记录

依据用户最新确定的时点，租借与敌队生成时记录不可变的 `factoryOriginalHeldItemId` 和战斗当前的 `factoryHeldItemId`。战斗消耗、拍落或替换只更改当前字段。战果结算恢复玩家队伍的 HP、PP、异常与临时状态，但保留本场战斗结束时的当前持有物；结果、换怪与组末基地页面因此可显示消耗后的状态。选择继续或换怪、准备下一场战斗时，`prepareFactoryPartyForBattle` 才按当前队伍每个成员自己的原配字段恢复持有物，同时恢复队伍战斗状态。换入敌方成员沿用其原配字段，重复准备结果相同。生成对手失败时撤回已准备的队伍。

存档升级到 schema v12，旧版按已有备份与重新开始流程处理。READY 快照的租借、玩家和敌方成员都必须带合法原配字段；各阶段允许当前道具已消耗。非法或缺失原配字段仍进入损坏存档保护，不能从当前道具猜测来源。

每场工厂战果通过一次本地写入提交：战后队伍、`ROUND_RESULT` 快照与钱包修订一起落盘；前六胜虽不发 BP，也提交零 BP 战果。写入失败保留战斗快照和同标签页重试意图，重复提交不重复发 BP。旧 BATTLE 自动保存不能覆盖同场结果、换怪或可续基地快照。下一场达到可操作状态时，既有稳定战斗快照自动保存将已返还持有物及新场次一同落盘；旧场次快照不能覆盖它。结算遇到较新钱包修订时保留其语言、图鉴等其他较新字段。

静态测试覆盖战后仍显示消耗、下一战按原配返还、无原配、重复准备、敌方消耗后换入、组末结果仍消耗、下一场快照写盘、战斗中刷新、写盘失败重试、重复结算、旧快照回滚，以及较新存档字段保留。浏览器和实体手机试玩留给 player/reviewer：需覆盖换怪、跳过、第 3/6 胜奖励节点和第 7 胜组末，并在下一战可操作后刷新核对持有物。
