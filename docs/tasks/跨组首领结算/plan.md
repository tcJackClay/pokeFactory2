# Classic 跨组首领结算验收计划

## 依据与现状

- 《公开版规则定稿.md》已确定 Classic 七战整组胜利才发工厂单打 BP，败退本组 0，真实工厂首领额外 10，余额上限 9999。第一至第九世代在设置中互斥单选，当前九代扩展随机池不等同于原型固定 Frontier set。
- `docs/tasks/组末BP结算/runtime.md` 已在模拟手机视口走完第一组：前六胜 0，第七胜 +3，返回基地刷新不重发；多数胜利用 DEV Win 辅助。续到第 8 战、跨页检查点、第一战败退 0 也有独立样本。第二、三组及实际首领没有同一挑战的浏览器闭环。`docs/tasks/首局租借加载优化/runtime.md` 的第一、九代六卡与首战只证明对应样本可玩，九代敌队来源尚未全验；点击耗时不包含全部 BOOT 预取成本，三次同条件性能门槛未通过。
- 静态入口已存在：`factoryRewards.ts` 的组 BP 表，`factoryBrain.ts` 的 21/42/后续周期，`factoryTrainerTemplates.ts` 的 `TRAINER_NOLAND`，`useFactoryFlow.ts` 的训练家与对手队伍生成，`usePokeFactoryGame.ts` 以当前训练家 ID 给 `useBattleController.ts` 传 `isFrontierBrain`，`saveManager.ts` 以挑战 ID + 组号去重结算。现有测试覆盖表值和首领条件；本任务先运行验收这些组件的连接，再按具体失败修复，不预设它们已在玩家流程正确生效。

## 最小执行范围

1. 使用隔离的新 v10 存档，在设置中固定一个世代，连续从第一战走到第 21 战；不要靠 DEV 直接跳到第 21 战作为主证据。每场记录 `stage`、训练家 ID、三只敌队的 `speciesId`/形态与来源、胜负、钱包、`settledThrough`、`brainSymbols`、工厂快照状态。首轮可选第九代以同时检查固定 set 不覆盖时的单世代扩展对手；另取第一代短样本核对有参考训练家池时仍不会混入其他世代。形态按项目已定义的世代映射判定，不只看形态 API ID 数字范围。
2. 第 1～6、8～13、15～20 胜后 BP 不变。第 7 战普通组末 +3，钱包 3、`settledThrough=1`；第 14 战普通组末 +3，钱包 6、`settledThrough=2`；第 21 战必须确认为实际 `TRAINER_NOLAND`，基础组 BP 4、首领额外 10、实际到账 14、钱包 20、`settledThrough=3`、象征数由 0 变 1。普通第 7/14 战即使 UI 称“首领战”，不能给额外 10。第 21 战若对手身份不是 Noland，不能靠 `stage===21` 强行加奖，须回到对手生成链修复。
3. 在第 7、14、21 战结算页和返回基地后分别刷新、重开结果、继续下一组；余额、组键和首领身份不重复、不丢失。第 7、14 战后的继续过程包含加载窗口刷新和失败重试；成功形成下一战稳定快照后才释放旧 BASE 检查点。第 21 胜继续第 22 战时钱包保持 20。另用已有非零 BP 的隔离存档在下一组败退，确认该组 0 BP、此前 3/6/20 BP 保留。
4. 用隔离可复现状态专项检查第 42 战和已获两个象征后的 21 战周期；明确区分“按合法连续挑战推进的运行证据”和“DEV/人工种子状态只验证分支”。按表第 6 组基础 5，真实首领加 10；不得以任意第七场的 generic boss 标记代替身份。额外样本不替代第 1～21 战主线。

## DEV 辅助与真实玩法边界

- 为在有限时间内检查跨组连接，可使用可见的 DEV Win 完成部分战斗；记录每场使用情况、运行版本和操作顺序，不写成自然通关。每组至少一战用正常出招并完成战斗回合，组末、首领出场、换怪/跳过、BP 持久化和第 21 战身份仍必须由真实页面状态与存档证明。
- 公开版最终验收仍需独立从新档正常操作赢完整七战，并覆盖普通换人、道具、战败、弱网及实体手机触控；本任务的 DEV 辅助跨组记录只能证明状态路由、对手生成与结算链。

## 静态与运行验收

- 静态：运行现有 BP 表/首领周期/组键幂等测试、类型检查和生产构建；若运行失败才补对应回归测试。核对 `isFactoryBrainStage`、模板选择、对手身份快照、结算传参链；覆盖切世代后新局对手仍只来自选定池，首领与普通第七战标记不混。检查余额 9999 上限，已有历史组不可再结算。
- 运行：使用真实前端 + Go 服务，以 `390×844` 为主记录 stage7/14/21 的结算截图、钱包前后、训练家 ID、三只敌队世代、`runId`、`settledThrough`、象征数、刷新与继续；`844×390`、`320×568` 复核关键操作可点。保留网络失败/控制台错误和内容版本。所选九代单池测试至少覆盖第一代与第九代，另外七代逐池检查可作为同规则后续矩阵，不把两个样本宣布为九池全验。手机模拟视口通过后仍需实体手机复核。

依赖：首局租借至少稳定产出六卡，跨页暂停挑战快照修复已通过指定路径；不依赖未定稿的商店商品、培育、Rogue 或每日任务。若第 21 战身份/奖励失败，先修主循环与幂等，不扩展新玩法。
