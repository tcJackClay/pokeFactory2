## 🔵 补充规则（用户 2026-09-27 新定，不在原 9 条内）

### 10. 持有物唯一性与回池：单一种类仅存 1 件，替换/舍弃即回池　✅ 已决定（2026-09-27）

| 项 | 内容 |
| --- | --- |
| **用户决定（2026-09-27，作用域已收敛）** | 「只需要将道具限制数量 1，就可以同时满足队伍和掉落池的数量补充；道具替换或者舍弃后重新回池」 |
| **规则表述（定稿）** | 任意时刻，**单一种类道具在整局中最多只存在 1 件实例**。该唯一实例只可能处于两种位置之一：**在队**（装备于三名队员之一）或**在池**（可作候选）。**候选池 = 已获准名单 `H` − 当前在队装备集合**。道具被**替换**或被**舍弃**时，**立即回到候选池** |
| **一条约束同时解决两件事** | (1) **队伍唯一性**：三名队员持有物互不重复、同批四卡互不重复（原作 Item Clause）；(2) **池子不枯竭**：跨组派发不会让候选池单调递减 |
| **明确排除的读法** | **不存在持久化「已获得」台账**（下文旧读法 B）。同一 ID 不会被永久移出候选池，因此第 3 组起不会跌破四张 |
| **关键推论（硬前提，必读）** | 回池只解决**跨组**不枯竭，**不改变单节点候选下界**：派卡瞬间三名队员恒占 3 件不同道具 → `候选数 = \|H\| − 3`，要凑满四张仍须 **`\|H\| ≥ 7`**。因此**第 1 条（七件保底）仍是硬前提**，不能因「反正会回池」而退回五件 |
| **不触发回池的情况** | 战斗中被打落/消耗属「暂时不在手」：按既有「下一战开战前按本局返还基准返还」语义，该件**仍在队**，不回池。**回池只由「装备替换」或「主动舍弃」触发** |
| **代码口径** | 候选池**每次开奖励节点时按当前装备重算**；不得落成持久化「已获得」集合，也不得用「本局已出过卡」的历史做去重 |
| 参考实现依据 | `reference/pokeemerald-expansion/src/frontier_util.c:2046–2073` 的 `AppendIfValid()`：同一队伍内，物种重复（2057–2060 行）或**持有物重复（2062–2068 行）直接拒绝收录**——即原作 **Species Clause + Item Clause**。`battle_factory.c:297/458/698` 另阻止敌方队伍生成与玩家队相同持有物，以保证战后任何换怪都不破坏该条款 |
| 与 Bulbapedia 记载一致 | Gen IV：初始 6 只租借「**each holding a different item**」；Gen III：敌对队伍被阻止携带与玩家队相同的持有物，「to ensure that no trade the player can possibly make after the battle will cause the resulting team to violate Species Clause or **Item Clause**」 |
| 本项目已有规则 | 《规则定稿》「换装后三人持有物不得重复，按本局返还基准查重」——与本条同源 |

**作用域收敛（已决定：采用 C）**

| 读法 | 状态 | 说明 |
| --- | --- | --- |
| **A. 队伍内唯一（原作 Item Clause）** | ✅ 已并入 C | 三人持有物互不重复、同批四张卡互不重复——由本次「数量 1」约束直接覆盖 |
| **B. 整次挑战内仅可领取一次** | ❌ **已否决** | 需「已获得」台账，候选池随组数单调递减。以 `\|H\| = 7` 推演：第 1 组取 2 件、第 2 组取 2 件后，第 3 组第 3 胜起候选降至 **3 张**，**四卡保底失效**；若采用必须把 `\|H\|` 扩到 `≥ 7 + 2 × 组数` |
| **C. 数量 1 + 替换/舍弃回池（用户 2026-09-27）** | ✅ **采用（定稿）** | = A 的唯一性 + B 想要的「不同时持有两件同名道具」效果。因回池，候选池**恒等于** `H \ 在队装备`，**不随组数衰减**；同时单节点下界仍为 `\|H\| − 3`，故 `\|H\| ≥ 7` 不变 |
