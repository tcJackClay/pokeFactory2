# 扩池规则设计（单线工厂奖励 · 持有物扩池与四卡生成）

本文件是 `docs/tasks/单线工厂奖励/design.md` 在「持有物扩池与四卡生成」专题上的**继承与定稿**，不推翻其已定玩家行为。上游 Rogue 商店的**价格、库存概率、解锁进度一律不搬**；本项目规则以《docs/公开版规则定稿.md》为准。本文件不改代码，也不改规则定稿；如需变更规则定稿，统一写在 §4「建议规则定稿变更」。

来源标注约定：**用户决定** = 已确认；**参考实现** = 可追溯到固定 Rogue expansion `a6adfcf1…` 或参考工厂；**设计理论** = 《宝可梦对战工厂_项目设计框架_v1.md》；**设计者选定（待用户确认）** = 本文件新选的数值/取舍，必须由用户拍板。

---

## 0. 问题陈述与数量下界（本条为定稿结论）

用户已确认的起始持有物只有 5 件：`scope_lens`、`quick_claw`、`kings_rock`、`choice_band`、`focus_band`。产品要求**每组第 3、6 胜后四张不同且可领取的卡**，且三名队员的持有物本局不得重复（**用户决定**）。

设 `H` 为「已获准、可对当前队伍任一成员装备、效果经验收的不同持有物 ID 集合」；`E` 为三人**下一战返还基准**的非空装备 ID 集合（用户要求 `|E| ≤ 3` 且互不重复）。在**不依赖 TM 组合**的前提下要保证四张不同且可领取：

- 最坏情况三人各占一件：`|H \ E| = |H| − 3`。
- 要 `|H \ E| ≥ 4`，必须 `|H| ≥ 7`。

`5 − 3 = 2 < 4`，所以**当前五件构成 Stage 2 的设计缺口**（**参考实现/数学下界**，见 `four-card-coverage-analysis.md`）。**定稿结论：独立于 TM 组合保证四张的可执行方案是把通用持有物保底池扩到 7 件**，而不是在运行时补位。

同时明确一条口径边界（**用户决定**的延展）：本规则保证的是「四张**不同且可领取（可装备）**」，**不保证**每张对当局队伍都必然产生战斗收益。卡面必须诚实区分「可装备」与「当局有触发场景」，不得为凑数谎称一定有效（见 §2.3）。

## 1. 扩池名单（定稿）

### 1.1 基础七件保底（采纳；附前提条件）

**定稿：采纳「已确认五件 + `heavy_duty_boots` + `loaded_dice`」作为基础保底池（共 7 件）。**

- 来源：**参考实现**（两件均出现在 Rogue expansion 独立持有物商店类别，且本项目 `itemEffects.ts` 已有战斗元数据与调用入口）；**设计者选定（待用户确认）**为该组合的最终批准，因为两件目前仅为提案，尚未获用户逐件批准。
- 理由：数量下界要求 `|H| ≥ 7`；这两件都**无物种限制**、可给任意租借队员装备，是把五件补到七件的**最低成本**解。
- **前提条件（全部满足才纳入）**：
  1. 两件各自完成战斗效果验收：厚底靴覆盖双方主动/濒死入场、重力与刷新；机变骰子覆盖只对合格 2–5 次连续招式改次数、无对应招式时的真实提示、多段 PP/日志与逐战返还。
  2. 卡面诚实：厚底靴只按「本项目当前支持的入场陷阱（隐形岩、毒菱）」说明，不宣称覆盖尖刺/黏黏网等未实现陷阱；**接地毒属性仍吸收毒菱、不被跳过**。机变骰子只对持有合格连续攻击招式的队伍有收益。
  3. 三人返还基准互不重复（用户要求），候选按**返还基准**而非本场当前持有物计算。
- 边界：七件保证的是「四张可装备/可领取」，**不是**「四张当局必然生效」。若产品改为要求四张都当局生效，七件的数量下界**不再成立**（见 §3.3 与 §5）。

### 1.2 第二层：15 件属性强化道具（准入条件与适用性判定）

名单（**参考实现** `items.h:5929–6150`，本项目 `itemEffects.ts` 已列 15 种）：`silk_scarf`(一般)、`charcoal`(火)、`mystic_water`(水)、`magnet`(电)、`miracle_seed`(草)、`never_melt_ice`(冰)、`black_belt`(格斗)、`poison_barb`(毒)、`soft_sand`(地面)、`sharp_beak`(飞行)、`twisted_spoon`(超能)、`silver_powder`(虫)、`hard_stone`(岩石)、`black_glasses`(恶)、`metal_coat`(钢)。

**定稿：纳入池，但作为「扩展可选层」，不承担四卡数量保底。** 准入与适用性判定规则如下（**设计者选定（待用户确认）**）：

1. **倍率前置**：先把本项目属性强化倍率收敛为 1.2 倍（依据 `include/config/item.h:15`，见 §2.1），并完成伤害结果测试，才允许开放这一层。
2. **适用性判定（该卡成为「当前队伍适用」候选的充要条件）**：当前三人中**至少一人**的某一招满足全部三条——
   - **已装备**：该招位于该成员当前招式栏内（未被替换/遗忘）；
   - **可造成伤害**：排除纯变化招式；
   - **属性匹配**：按该招**实际攻击属性**匹配道具的强化属性。
3. **排除**：纯变化招式、已失去的招式、当前三名成员均不匹配的道具，都不作为「当前队伍适用」候选；没有匹配招式时**不得**伪称当前适用。
4. **不用于数量兜底**：当基础七件已足以凑满四张时，属性强化只用于扩大玩家选择空间；它们**不计入** §3.3 的保底数量下界。

### 1.5 准入总则（可判定）

一件持有物**可发卡**，当且仅当同时满足：(a) 属于 §1.1–§1.3 的定稿名单；(b) 无物种限制，或当前队伍确有满足物种条件的成员；(c) 已完成本项目战斗效果验收；(d) 三人返还基准不含该 ID；(e) 至少存在一个合法装备对象，且换装后三人返还基准不重复。任何一条不满足则**不出卡**。

## 2. 效果口径收敛

### 2.1 属性强化倍率（1.2 vs 1.1）

**定稿：采用 1.2 倍。**

- 依据：**参考实现** Rogue `include/config/item.h:15`（`I_TYPE_BOOST_POWER=GEN_LATEST`、`TYPE_BOOST_PARAM=20`）与 `src/data/items.h:17–21` 为 20%（即 1.2 倍）；本项目当前为 1.1 倍。
- 理由：用户已把 Rogue expansion 定为本项目持有物来源与效果参考（**用户决定**）；属性强化属于该商店类别，保持「同名同效」，避免同名道具在参考与本项目间行为不一致。
- 标注：**设计者选定（待用户确认）**——虽然是对齐参考实现，但改变当前数值属平衡改动，须用户拍板；且须以**逐属性伤害结果测试**证明，十五件逐件通过才逐件开放。

### 2.2 气势头带 `focus_band`（消耗 vs 不消耗）

**定稿：采用 Rogue 口径「成功挺住后本场不消耗」，同一场战斗内每次合格致命伤可独立判定。**

- 依据：**参考实现** Rogue 只在目标持有 **Focus Sash（气势披带）** 时移除物品；Focus Band（气势头带）仅设置挺住标志、**不消耗**。本项目当前实现为成功挺住后消耗。
- 理由：(1) 用户已把 Rogue expansion 定为本项目持有物**效果参考**，一致性优先；(2) 本项目未纳入气势披带，若气势头带也消耗，则与「返还基准」语义叠加后效果退化为「每场至多一次」，与 10% 概率保命道具的定位不符；(3) 保持不消耗使它在三人唯一约束下是稳定的第三/第四张候选。
- 标注：**设计者选定（待用户确认）**。若用户不采纳 Rogue 口径而保留「消耗」，则**必须明确标注为「本项目扩展规则」，不得宣称已对齐 Rogue**；无论采用哪种，都须同步展示、存档与逐战返还验收。

### 2.3 厚底靴 `heavy_duty_boots` / 机变骰子 `loaded_dice` 的效果条件与诚实标注

**定稿：两件的效果条件如下，卡面与候选提示必须按「诚实说明适用性」呈现。**

| 道具 | 效果条件（何时有收益） | 卡面/提示要求 |
| --- | --- | --- |
| `heavy_duty_boots` | 入场时**已铺设入场陷阱**（本项目现支持隐形岩、毒菱）才有收益；**接地毒属性仍吸收毒菱**，不跳过该吸收。 | 只按本项目已支持陷阱说明；**不得**宣称覆盖尖刺/黏黏网等未实现陷阱；无陷阱铺设时不得宣称本场必然有效。 |
| `loaded_dice` | 持有者**已装备合格的 2–5 次连续攻击招式**时才改变次数；无此类招式时**无收益**。 | 无合格招式时不得伪装成当局有效；应呈现为「可装备，但当前无对应触发场景」。 |

**共性要求（硬规则）**：候选生成以保证「可装备/可领取」为数量下界（§0、§3），但**允许**出现「可装备但当局无触发场景」的卡片；此时卡面/选择提示必须**如实标注**适用性，**不得为凑数谎称当局一定有效**（**用户决定**的延展）。

## 3. 四卡生成规则

### 3.1 候选枚举与过滤（按「本局装备返还基准」）

1. **基准口径**：一律按每个成员**本局装备返还基准**（初始=租借原配；领取奖励装备后=奖励装备）计算，**不得**用本场可能被消耗/拍落的当前持有物字段规避查重（**用户决定**）。
2. **持有物候选** = `H \ E`：`H` 为 §1 定稿名单中满足 §1.5 准入的 ID 全集；`E` 为三人返还基准 ID 集合。已在三人任一装备位的 ID **不出卡**；对原持有人「原物再装备」不算可领取。
   - **唯一性（**用户决定 2026-09-27**，参考实现 Item Clause）**：单一种类道具仅可获得一个，不得重复。与 `reference/pokeemerald-expansion/src/frontier_util.c:2046–2073` 的 `AppendIfValid()` 同源——该函数对队伍内重复持有物**直接拒绝收录**（2062–2068 行；2057–2060 行为同款物种条款）。作用域为「**队伍内唯一 + 同批四卡唯一**」，与既有「换装后三人持有物不得重复」规则一致，无需新增机制。是否进一步收紧为「整次挑战内仅可领取一次」见 `decisions.md` §10——**该读法会使候选池随组数递减、约第 3 组起跌破四张，采用前必须同步扩大 `|H|`**。
3. **TM 候选** = 按固定 Rogue expansion 普通 profile 学习判定、**当前队伍可学且未掌握**、且**已完成本项目映射与战斗效果发布准入**的不同 TM ID 联集。**未验证 TM 不得发卡**；旧 `getLearnableMoves` 的全量随机抽样不能作为候选来源（**用户决定** + **参考实现**）。
4. **其他卡** = 另经用户批准的战斗道具（如 `battle_atk`/`battle_def`，是否入池见 §5）。
5. **每张卡**至少给出一个合法装备对象；换装后三人返还基准不得重复（**用户决定**）。
6. **换怪**后须先核验整队装备唯一性，再重算候选；不能擅自丢弃敌方原配道具。

### 3.2 抽取权重与类别配比

- **首版不强制固定 ITEM/TM 配比**（**设计者选定（待用户确认）**）：从已验收、ID 不同的合格候选集合中**不放回等权抽样** 4 张。依据 `held-item-pool-plan.md` 的建议。
- 理由：当 TM 准入 allowlist 尚未齐备时，固定配比会带来「某类下限不足」的额外失败点；等权抽样在数量下界已满足时最稳，且不把未验收 TM 当兜底。
- **权重置于独立配置**，不沿用旧 `FREE_REWARD_TYPE_WEIGHTS`、十次重抽或旧 `POKEMON`/`EVOLUTION` 池（**用户决定**）。
- 若用户改为固定比例（如 2 ITEM + 2 TM），须**分别证明**各类下限（`|H \ E| + |O| ≥ 2` 且 `|T| ≥ 2`），并重跑四卡覆盖验证。

### 3.3 候选不足时的处理（可执行方案 + 推荐）

先把两种「不足」分开，切忌混为一谈：

**(A) 数据/加载/计算失败导致的候选不足** —— 属错误路径：
- **留在奖励节点**，给可重试反馈；**不推进战次、不少给卡、不重复卡**（**用户决定**）。

**(B) 因产品边界导致的合格候选 < 4** —— 属规则设计问题：
- 现状：基础七件已使 `|H \ E| ≥ 4`，**独立于 TM 即可凑齐四张**，故正常不会发生。
- **明确禁止**：用重复卡、不可学/未验收 TM、旧奖池、空卡填空，或隐式少给卡。
- **推荐（可执行）**：当 `|H \ E| + |T| + |O| ≥ 4` 成立时正常不放回抽四张；把「可装备但当局无触发场景」的持有物**仍计为合法候选**（因为保证的是「可领取」，不是「当局有效」，见 §0/§2.3）。这样在七件保底下可稳定产出四张。
- **仅当用户进一步要求「四张都必须当局有效」时**，七件数量下界**不再成立**（`loaded_dice`、厚底靴都不必然当局有收益），此时**必须另定额外通用池或队伍级覆盖规则**，由用户拍板，**不得由代码自行补位**（见 §5）。

### 3.4 失败重试与领取语义

- 候选生成后**冻结**：刷新、重开、同版导入应保留已展示候选，**不重新抽取**。
- 领取事务：`READY → CLAIMED` 原子；**双击只领取一次**；刷新不得重复领取、不得复活被消耗/拍落的旧装备。
- 领取时选择队员并确认替换，旧物**直接移除、不进背包**；新物写入该成员**本次挑战后续每战开战前的返还基准**并即时显示为当前装备（**用户决定**）。
- 失败留在奖励节点重试，语义为：**不推进战次、不少给卡、不重复卡**（**用户决定**）。

## 5. 仍待用户定夺

| # | 需用户拍板 | 为什么不能由代码默认值代替 |
| --- | --- | --- |
| 1 | **基础七件中 `heavy_duty_boots`、`loaded_dice` 的最终批准** | 两件目前仅由设计者依数量下界与参考实现选定；是否作为奖励卡会改变玩家可见卡池，不能由默认值暗定。 |
| 2 | **属性强化倍率取 1.2（对齐 Rogue）还是保留当前 1.1** | 这是平衡数值改动：1.2 改变全部 15 件的强度，影响对战胜负，须用户确认。 |
| 3 | **气势头带采用 Rogue「不消耗」，还是保留本项目「消耗」** | 两种口径给出不同玩家行为（每场一次 vs 每次合格致命伤可判）；若保留消耗须标为本项目扩展规则，涉及「是否宣称已对齐 Rogue」。 |
| 4 | **白色香草 / 心灵香草是否属禁止的「回复类」** | 二者**不回复 HP/PP**，只解除降能力/心智妨碍；是否落入用户「无回复类奖励」的边界须用户定义，不能由实现自行归类。 |

## 6. 验收要点（与规则一一对应）

- 三人已装备基础七件中任意三件、且 TM 候选为零时：**仍能产出四张不同、无同名、每张至少一个合法队员**的卡（**设计者选定（待用户确认）**的下界结论，须逐队枚举证明）。
- 候选按**返还基准**过滤：战斗中消耗/拍落不改变候选；换怪后重算且保持三人唯一。
- 厚底靴、机变骰子、气势头带：各自有双方战斗结果断言（厚底靴不跳过毒属性吸收；机变骰子仅对合格连续招式改次数；气势头带依 §2.2 定稿可重复触发或按扩展规则消耗）。
- 属性强化：匹配伤害招式 1.2 倍、不匹配与变化招式不增伤；十五件逐件通过才标可发；无匹配招式时不伪称适用。
- 事务：第 3/6 胜先换怪再生成；冻结四卡刷新不变、双击只领取一次、失败留节点重试；同版保存恢复后装备、候选、领取状态与下一战返还一致。
- 发布门禁：不以只读源表数量或元数据存在代替伤害/行动结果；确定性夹具覆盖极端三件占用与 TM 零候选，浏览器自然长局与实体手机另验。
