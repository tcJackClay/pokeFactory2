# 功能规格

## 1. 触发条件

玩家在战斗中对在场宝可梦下达一次指令——选择一招并确认，或选择换人并确认。

## 2. 初始状态

- 双方各一只在场宝可梦（单打），HP / PP / 异常状态、能力等级已知。
- 天气、场地、双方顺风 / 戏法空间等回合末计时已知。
- 双方队伍后备列表已知。
- 玩家指令尚未提交。

## 3. 流程

一次玩家指令构成**一个轮次**。轮次内：

1. **确定顺序**：在轮次开始时一次性决定双方行动顺序（比较优先度、速度、先制之爪触发）。顺序决定后不再重选。
2. **第一行动**：按顺序执行。行动可能是出招、主动换人，或因妨碍（睡眠/冰冻/畏缩/混乱自伤/守住/未命中/免疫/招式失败）而跳过。
3. **濒死与补位**：若一方在场者濒死，先完成合法补位。玩家侧需选人时轮次暂停等待玩家选择；敌方侧自动补位。补位因入场陷阱再次濒死则继续补位，但该侧本轮的**行动机会已被消耗**，不复活。
4. **第二行动**：以补位后新的在场者为目标。若原行动者已倒下或因状态无法行动，记为该侧跳过，**不由补位成员代打一招**。
5. **回合末结算**：第二行动完成或跳过后，**恰好一次**结算天气伤害、中毒/烧伤等残余伤害、顺风/戏法空间/雪景等计时、回合末补位。
6. 回合末结束后才开放下一次玩家输入。

> **状态受阻检查**（来自现行实现口径）：妨碍判定必须在该侧**真正的行动机会开始时**执行一次。睡眠回合数、混乱自伤、果实等效果不得因敌方先手而被提前或重复推进。

> **刷新语义**：进行中的回合不得持久化半成品。稳定玩家回合快照只在轮次完成（无悬挂补位、无未完成异步日志）时生成。进行中刷新回到**最近的完整稳定检查点**，不得保留已扣 PP / 已受伤但未完成第二行动的半回合。

## 4. 终态

- **回合完成**：双方各行动或跳过一次，回合末结算一次，开放下一次输入。
- **战斗结束**：一方队伍全灭 → 立即终止轮次，走胜负结算；**不执行**未行动的招式，**不重复**回合末结算。
- **刷新 / 关卡切换 / 卸载**：旧轮次标识立即失效，旧异步回调不得写入新战斗。

# 边界情况

> orchestrator 拥有。上游规则未覆盖但本实现必须处理。

- **敌方先手**：敌方行动后轮到玩家，玩家行动完毕才回合末；不得出现 `ENEMY→PLAYER→ENEMY` 的第二次敌方行动。
- **同速 / 先制之爪改变顺序**：顺序只在轮次开始决定一次；先制之爪的提示与顺序必须一致。
- **第一行动击倒对手**：被击倒一侧补位后，存活且尚未行动的原成员打**当前新目标**，不是幽灵目标。
- **双方同时濒死**：按胜负结算，不继续第二行动。
- **入场陷阱连续倒下**：连续补位直到有存活者或全灭；已消耗行动的一侧不因补位重获行动。
- **主动换人**：换人本身是该侧一次行动；换入后若对方尚未行动，其已选招式对新成员结算。
- **长日志**：每个 `await` 之后重新核对轮次标识与成员身份；日志等待期间不启动新轮次。
- **连续点击**：创建轮次时立即加同步门闩，直到完整回合或明确中断才解除；不能只依赖异步 React busy 状态。
- **回合中天气/异常计时**：不得在敌方先手后、玩家尚未行动时递减；完成轮次时恰好结算一次。
- **战斗中持有物被消耗/拍落**：当前持有物字段可为空，但**本局返还基准**字段不受影响（查重与返还用的是基准字段）。

# 验收条件

- 一次玩家指令 = 一轮；双方本轮各行动一次（或合法跳过）；任何招式 PP 只扣一次；回合末只结算一次；下一轮只开放一次输入。
- 敌方先手、玩家先手、同速、先制之爪改变顺序四种情形均不出现敌方二动。
- 未命中 / 守住 / 免疫 / 睡眠 / 冰冻 / 畏缩 / 混乱自伤等早退分支：该侧记为已行动或跳过，合法剩余行动照常执行；无空轮、无重演、无提前的天气/中毒伤害。
- 玩家/敌方主动换人、第一行动击倒、双方濒死、入场陷阱击倒补位：已行动者不再攻击；全灭只结算胜负。
- 刷新、连续点击、关卡/运行切换、卸载：旧轮次回调不写入新战斗；刷新恢复上一个**完整**回合，无半轮 PP/HP 漂移。
- 顺风 / 毒菱 / 隐形岩 / 天气计时在轮次修复后**必须重验**（旧样本在修复前取得，不得升级为通过）。

# Orchestrator 裁决（2026-09-26）

> 针对 `plan.md` §6「风险与隐含决策」8 项的逐条裁定。**programmer 必须按此执行**，不得自行改判。

**规则来源等级（风险 1）— 批准，按「实现口径」处理。**
本任务机制在《公开版规则定稿.md》中确无逐条用户可见规则；其依据为前序技术计划 + 毒菱边界实测失效链 + 宝可梦战斗正典语义。**不作为「发明机制」处理**，但 traceability 等级记为「实现口径 ≠ 设计定稿」。裁决理由：这是**修复缺陷**（行为明显违反「双方每轮各行动一次」的正典共识），不是新增玩法；等设计定稿会无谓阻塞 P1。

**敌方换人视为先手（风险 2）— 批准。**
依据正典：换人在宝可梦战斗中的优先度为 +6，先于一切招式。**必须在 plan 中注明依据是正典换人优先度**，不得表述为「本轮自行选定」。

**早退分支收敛（风险 3）— 要求本轮一并完成，不留在尾巴。**
理由：PRD 明确要求每个早退汇聚到同一次「本侧已行动」记账；且交接文档已警告 TM 跨回合招式会**放大**未收敛的轮次缺陷。结构目标未达成即视为未完成。

**`failed` fail-closed 死锁（风险 4）— 改为可恢复。**
理由：现行产品规则要求「重复游玩没有死路或不可恢复状态」，要玩家刷新才能继续是不可接受的。要求：释放 `roundActionLockedRef` 与 `roundTransactionActive`，恢复 UI 可用，**同时保留「绝不写入半轮」的保证**（即失败时回滚到轮次起点语义，而非写入半成品）。
附带：`BattleActionPanel` 的 `|| 队长已倒下` 放行特例——门闩正确释放后应不再需要，**优先移除该特例**；若确有保留必要，须在 log.md 说明理由。

合法失败（换人被大闹/踩影拦、特殊触发道具提示、极巨化石不匹配）必须返回 `SKIPPED`，**不得**判定战斗结束。战斗结束必须由「一方队伍全灭」单独判定。
