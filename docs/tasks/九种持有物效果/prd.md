# PRD：九种持有物效果与状态恢复

orchestrator 拥有。来源：`docs/公开版规则定稿.md`、`docs/tasks/工厂内容准入/design.md` 及2026-10-13用户对气势头带/王者之证的决定。本任务须在状态命中修复及永久收藏捕捉接线合入后才修改战斗控制器；可以先研究方案。

## 边界

仅九件已批准持有物的实际效果、文案一致性、消费/不消费和下战返还；不扩池，不改券价，不引入属性强化或光粉。依据固定 Rogue `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014` 及已批准香草参考，不能用常识替代源码的具体条件。道具被消费/拍落不得误改下战返还基准，三人装备基准仍不重复。

## 功能规格

1. 焦点镜：暴击等级+1、非消费，按现行暴击规则实际参与判定，不将状态招式变成伤害。
2. 先制之爪：合格时20%发动，只影响同优先级顺序，不超越更高优先级，不重复行动，不消费；无发动仍按既有顺序。
3. 王者之证：用户已明确按固定参考独立进行合格的10%畏缩判定。与招式原有畏缩机会独立，不简单相加、不取max。正常20%招式对应合并28%、30%对应37%仅为无其他修正下的推导。固定源对多段、替身、免疫、强行等适用性须按设计核对落实。目标本轮已经行动不能被倒扣一次行动，畏缩不能错误跨回合保留。非消费；只作持有道具不兼进化用途。
4. 讲究头带：物攻1.5倍并锁定招式，特殊攻击不获这项加成；换人/失去道具及PP/招式不可用按固定参考已接入规则核对，不只有伤害效果而无锁招。依据内容准入设计 S 节，双方全部招式均不可用时使用最小挣扎兜底，包含锁定招式零 PP 而其余招式仍有 PP 的情况；不解除讲究锁、不替换四招、不扣原招 PP。挣扎按固定源为威力50物理接触、优先级0、跳过普通命中但保留保护等门禁，无 STAB/属性相性，成功攻击链反作用为最大 HP 四分之一向下取整且至少1。固定参考中的魔法防守豁免与坚硬脑袋不豁免须保留；不扩写 AI 或未有能力系统。
5. 气势头带：用户已明确合格致命打击10%撑到1HP，触发后不消费，后续合格打击可再次判定；多段逐次处理，不给毒/天气等间接伤害套攻击挺住。不能与气势披带混用。
6. 厚底靴：入场免受已支持隐形岩/毒菱效果，无陷阱时不声称有收益；固定参考接地毒属性即使穿靴仍先吸收毒菱。不免疫普通战斗伤害，双方换人/补位各一次。
7. 机变骰子：已定2–5连续攻击范围得到4或5次，连续攻击特性已保证次数时不额外改变；单发和固定次数不误判收益，目标早倒下即停，同次招式只扣一次PP。特殊多段招式未经核准不扩大适用范围。
8. 白色香草：实际负等级恢复0、正等级保持，实际恢复后消费一次；自身下降也适用。未命中/被挡或没有负等级不因该行为消费。复用状态任务结果并在整合代码补必要回归。
9. 心灵香草：对固定参考启用配置下的迷恋、挑衅、再来一次、无理取闹、定身、回复封锁六项完整列表按已核源码解除并消费；无合格限制不消费，不治疗普通中毒/睡眠。各别名与同时状态不重复消费，下一战按基准返还。回复封锁当前自然租借可达，须依据内容准入设计 M5–M8 接通施加、已存在回复入口的限制、计时与清除，不能仅补受控状态标签：命中100、保护阻挡但穿替身，成功持续5回合，重复失败不续期，香草当次动作清除；禁用招式的选招与出手都检查，吸取/睡觉等受限时整招不执行。按上游逐入口表区分目标、回复、损血与免疫，分担痛楚等明确例外保留。换人、新战清理及刷新计时一致。未实现接棒/祈愿等另列差距，不借本任务新增完整招式系统。

## 验收与证据

- 为每件建立规则→代码→静态→真实UI逐件表，列有效/无效、双方路径及未验交互。测试数不能替代道具效果。
- 气势头带须同一持有者多次合格致命打击仍有道具并能再触发，未触发和间接伤害对照；极端概率可使用标明的固定随机输入。
- 王者之证须证明独立判定接线、顺序与适用性；静态固定随机边界和多段逐击计数，真实UI观察应畏缩/不畏缩的行动与下回合恢复。不得以少量随机样本估计精确28%。
- 焦点镜/头带/骰子的数值由真实引擎可重复对照验证，UI至少验证已走该效果入口；概率与数值断言和视觉分别记录。
- 讲究锁招、靴入场、心灵香草完整限制列表及白色香草的实际变化都要有可观察状态；物品消费与返还基准分别检查。
- 挣扎须覆盖双方全零 PP、讲究锁零 PP、仍有合法招时不出现、无属性伤害、保护、反作用倒下与刷新。回复封锁须覆盖无香草的自然施加入口、即刻香草解除、重复/保护/替身、选招后被更快封锁、禁止回复但保留伤害/免疫的例外、5回合到期、换人及刷新；受控数值与自然正文来源分别标明。
- 使用真实Go+Vite、冻结最终SHA、390×844主视口并补320×568/844×390关键日志。受控招式/数值/随机来源逐例说明；原始招式若缺contact等字段不能把补注入称为自然正文通过。
