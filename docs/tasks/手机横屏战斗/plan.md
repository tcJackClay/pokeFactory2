# 手机横屏战斗实施计划

依据《docs/手机端试玩验收记录.md》：`844×390` 实际战斗可出招且页面无溢出，但战斗场景约 `205×115` 像素，状态字明显过小，主命令按钮约 36 像素高。目标是在该横屏视口读清双方状态并能稳定点选命令和招式。

`BattleScreen.tsx` 将页面分成顶部、场地、命令三行；`src/index.css` 的横屏短高媒体查询把场地行设为 `minmax(88px, 1fr)`、命令区设为 `clamp(132px, 40svh, 156px)`，且按钮与文本缩至 36、9 像素。`BattleFieldPanel.tsx` 将逻辑 `320×180` 场景按容器的宽高较小值等比缩放。短高横屏时场地区高度成为缩放瓶颈，不能只提高图片 CSS 尺寸。

实现顺序：先测量 `844×390` 的顶部、场地、命令区真实矩形与可点控件；再调整短高横屏布局，为场地争取高度，必要时将命令区改为横向紧凑布局，并保持五个主命令与四个招式能直接触达；最后核对状态卡、精灵、战斗日志和按钮字号。保持逻辑场景宽高比，避免裁切状态或战斗演出。主要文件为 `src/index.css`、`BattleScreen.tsx`、`BattleFieldPanel.tsx`、`BattleActionPanel.tsx` 和相关状态卡组件。若 CSS 调整足够，无须改战斗逻辑或存档。

静态验收：`npm run lint`、`npm run build`；视口自动检查页面无横纵溢出、主要按钮可见且命中区域达到产品确认的手机触控尺寸。运行验收：用当前 Go 服务与实际战斗状态在 `844×390` 完成出招、换人、查看状态、展开日志；记录场景实际矩形、双方 HP 和状态可读性、按钮矩形、点击结果及截图。以 `390×844`、`320×568` 复核竖屏无倒退。侧边浏览器通过后再以实体手机浏览器检查地址栏变化、旋转和触控误点。
