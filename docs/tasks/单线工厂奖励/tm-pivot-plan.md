# TM32 急速折返与 TM15 伏特替换实施和验收计划

基线为 `origin/dev` 的 `246e038`。规则依据是本地固定 Pokabbie/pokeemerald-rogue `expansion` 源码 `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014`：`src/data/party_menu.h` 把 TM15 指向 `MOVE_VOLT_SWITCH`、TM32 指向 `MOVE_U_TURN`；`src/data/battle_moves.h` 两招均为威力 70、命中 100、PP 20 的 `EFFECT_HIT_ESCAPE`，分别是电属性特殊攻击和虫属性物理接触攻击。`data/battle_scripts_1.s` 的 `BattleScript_EffectHitEscape` 先完成正常攻击，再在未发生“招式无效果”、战斗未结束、施招者可换人时进入 `BattleScript_MoveSwitch`；`test/battle/move_effect/hit_escape.c` 对命中换人、战斗结束不换、没有存活后备不换有直接断言。

## 当前入口和依赖

- `src/features/game/data/battle/moveEffectTable.ts` 尚无两招的 pivot 效果 ID；`src/features/game/hooks/useBattleController.ts` 的 `executeTurn` 会扣 PP、结算命中／守住／属性免疫／伤害／濒死，然后直接交接 `setMainBattleTurn`，所以现状仅造成普通伤害。不能在伤害后直接调用普通 `switchPokemon`：它要求玩家回合并自行把行动交给敌方。
- `handleAttack` 在玩家点招后决定双方先后；敌方先动时 `runEnemyAutoAction` 后才继续玩家攻击。玩家先动时 `executeTurn` 结束后把回合设成 `ENEMY`，随后 `enemyTurn` 自动调用 `runEnemyAutoAction`，其决策可能重新取样。这两条路径需要把已选行动、是否已行动及目标换入信息带过 pivot，避免额外回合或打向旧成员。`liveBattleStateRef` 只可用于读取提交后的最新队伍，不代替待执行行动记录。
- 现有 `clearSwitchingBattleState`、`enterBattlefield`、`reportEntryHazards`、`sendOutNextEnemy` 已覆盖一般换人和补位；pivot 要复用其退场清理与入场陷阱，但单独处理行动交接。`resolveEntryHazards` 当前只实现隐形岩；若 TM24 毒菱切片先合并，同一入场调用应自动覆盖两种陷阱。
- `usePokeFactoryGame.ts` 的稳定快照只在可操作的玩家回合生成，战斗中非稳定态保留前一个快照。玩家选 pivot 后备的等待界面属于未结算完的一次行动，刷新时必须恢复到上一个完整稳定回合，不能保存已扣 PP／已伤害但未换人的半回合；或者先实现含待执行行动的完整事务快照，首版建议前者。

## 最小实现

1. 给两招统一标记 `HIT_ESCAPE`，保留 API 提供的属性、威力、命中、PP、伤害类别与接触标记。若资料中的 `battleData` 覆写缺失，不允许走“通用伤害即支持”的路径。抽取纯规则判定：只有攻击实际命中且对目标有效、施招者存活、战斗未结束、有存活后备时才进入 pivot；无后备时攻击仍正常造成伤害和消耗 1 PP。伏特替换面对地面属性或其他电免疫、两招被守住或落空时均不换。若伤害被替身承受，按原型攻击有效的口径判定，并加独立结果测试；不要误把 `totalDamage === 0` 一概当失败。
2. 将 pivot 定义为同一行动的显式阶段：`ATTACK_RESOLVED → AWAIT_PIVOT_CHOICE（仅玩家）→ SWITCH_IN → REMAINING_ACTION/ROUND_END`。阶段持有原施招方、入场后备、对方已行动标志、待执行的对方招式与特效选择；选择界面只能选一个存活后备、不能攻击／普通换人／重复确认。敌方 pivot 用已有 AI 候选评估选择后备，不由玩家选择；无合法后备直接完成原攻击。所有队伍写入、日志和动画应以当前战斗 epoch 核对，防止异步旧回调继续结算。
3. 换出时只清除应在换人消失的状态，保留 HP、PP 与持有物消耗；调用统一 `enterBattlefield` 结算入场陷阱并报告。若新成员被陷阱击倒，走同侧濒死补位路径，不让已倒成员承受后续攻击。原型 `BattleScript_MoveSwitch` 的 `SWITCH_IGNORE_ESCAPE_PREVENTION` 表明招式换人可越过通常逃脱阻止；本项目普通 `switchPokemon` 会拒绝 `trapped`／`ingrain`，pivot 不得直接继承这一门禁。具体粘着特性及招式锁定的例外需用当前项目能力覆盖表核实，未实现项记录为边界，不能悄悄禁用 pivot。
4. 先动者 pivot 后，未行动者当回合原先选定的招式对**新入场的当前目标**执行一次，且入场陷阱先于该招式；后动者 pivot 后，本回合双方已行动，不再新增攻击。敌方先动 pivot 时，玩家原已点的招式仍由原玩家成员对敌方新成员执行；玩家先动 pivot 时，敌方原选的招式和行动承诺不重抽。若 pivot 的伤害击倒目标，先按原型与项目补位顺序处理目标及战斗结束，再决定施招者是否仍需换人，不能让一次伤害同时触发两条相互覆盖的换人流程。失败、守住和免疫分支保持现有回合推进。
5. 同一完整行动只扣一次 PP，包括命中后换人、无后备、未命中、守住和免疫；已选后备的双击不重复扣 PP、伤害或触发陷阱。刷新保护以最后稳定检查点为事务边界：半回合刷新可整回合重放，但不得保留半回合扣过的 PP 或造成的伤害；完成换人和剩余行动后才可进入新的稳定存档。若运行期间切到其他页面或自动保存，使用同一门禁。

## 结果验收

| 场景 | 断言 |
| --- | --- |
| 玩家先动命中，敌方后动；敌方先动命中，玩家后动 | 每侧本回合各执行至多一次原已选行动。前者敌方招式命中新入场玩家；后者玩家招式命中新入场敌方。速度／先制改变顺序时仍正确。 |
| 伏特替换打地面属性、两招落空、被守住 | 正常消耗一次 PP，无换人提示、无入场陷阱；免疫或守住的伤害为零。 |
| 命中但无存活后备；施招者倒下；击倒最后敌方 | 正常保留本次伤害与一次 PP，不产生非法换人；已结束战斗直接走结果。 |
| 命中替身、目标濒死但还有后备 | 按固定原型的有效命中和先后补位语义执行；成员身份、HP、PP、日志均与结算一致，不出现双补位或旧目标承伤。 |
| 敌方施放；双方各有隐形岩／毒菱 | 敌方独立选后备；换入只触发其所在侧陷阱一次。陷阱击倒后继续合法补位，未行动对手不能打已倒目标。 |
| 选择后备期间双击、刷新、退到其他页面 | 无重复攻击／扣 PP；刷新回到上一个完整稳定回合，队伍、PP、HP、陷阱均一致；不产生无法继续的半回合存档。 |

先写纯判定和行动阶段的结果测试，再写控制器集成测试覆盖两种先后顺序、双方 pivot、失败路径与陷阱补位。执行仓库既有 TypeScript、战斗测试和构建门禁。手机浏览器在 390×844 与 844×390 各完成两招的出招、后备选择、敌方未行动攻击、刷新恢复；记录战斗日志、队伍与 PP、HP、陷阱前后截图和控制台。用确定性战斗夹具覆盖免疫、守住、无后备与敌方施放；自然奖励抽到两张 TM 时再补奖励到战斗的贯通记录。模拟视口通过后仍需真机触控验收。
