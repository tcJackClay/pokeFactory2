# 顺风静态审查

基于 `c315fce` 审查。Rogue 原型按阵营维持四回合顺风，重复施放失败；当前纯规则、行动顺序、双方独立计时、换人保留、新战清零和状态面板与此一致。

已修复两处：同版 `READY` 存档中存在但损坏的双方顺风计时现在触发损坏存档保护；回合末的队伍、天气、场地与顺风结果现在在第一条异步战斗消息前一起提交。结果级测试以中毒扣血产生消息和队伍更新，模拟旧 effect 在消息播放时被清理，断言三类计时均已递减。`npm run lint` 和 43 项定向测试通过；未运行游戏。

仍有一个独立的濒死流程风险：`useBattleController` 的回合末 effect 在 `turn` 为 `PLAYER`、前一回合为 `ENEMY` 时计算结果；提交新的队伍数组会触发依赖变化及旧 effect 清理。若回合末毒伤、天气或持有物等产生待播放消息，消息播放的 `await` 后 `cancelled` 为真，随后直接返回，`playerLeadFainted` / `enemyLeadFainted` 分支的濒死提示与自动换人可能跳过。最小场景是只有一只前排宝可梦在回合末中毒致死、仍有存活后备、毒伤消息待播；应出现濒死提示和后备上场，但源码路径可能在此之前返回。这不是顺风独有，也不只限于消息：任何在队伍更新后到换人前发生的异步让出都可能暴露同一窗口。当前补丁只保证计时已提交，不改变换人控制流。下一切片应把一次回合末处理固定为独立事务或不随本次队伍更新取消的运行令牌，并以濒死后备上场、双方同时濒死和离开战斗时取消为验收场景；需浏览器实战确认。
