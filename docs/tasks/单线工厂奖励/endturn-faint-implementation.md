# 回合末濒死处理

技术计划：现有回合末 effect 在队伍和计时同步提交后播放异步消息。该提交会重建 effect 并执行旧 effect 的清理，因此旧闭包在消息后把普通依赖重建误判为离开战斗，跳过濒死与补位。修复时保留同步提交和消息顺序，以战斗实例令牌判断是否真正退出或换局；队伍更新造成的依赖重建不取消本次结算。用运行中标记保证一次回合交接只执行一次。把消息、濒死提示、双方补位的顺序编排抽为可测试函数，以受控 Promise 模拟消息期间的 effect 清理和真正离开战斗。验证中毒致死但仍有后备、双方同时致死、真实离场停止后续提示。

实施结果：回合末队伍与计时仍在第一条异步消息之前同步提交。普通依赖更新现在只清理旧 effect，不会中断该次回合末事务；只有组件卸载、离开当前战斗、换挑战局或战次时才停止后续提示与补位。运行中标记阻止同一次交接再次结算。中毒或天气伤害消息之后，按玩家濒死提示、玩家后备选择、对手濒死提示、对手后备出场的顺序处理。双方同时濒死且玩家仍需选后备时，对手出场不会把换人菜单改回招式菜单；玩家没有后备时避免同时安排敌方补位和胜利。

结果级测试用实际中毒致死的 `resolveEndTurn` 结果与受控异步消息模拟队伍更新后的旧 effect 清理，验证濒死提示和后备仍执行；另测双方同时濒死的顺序、玩家无后备、真正离开战斗时停止。`npm run lint`、聚焦 20 项测试、全量 175 项测试及 `npm run build` 均通过。未运行游戏，仍需 auditor 审查和 player 实战验收。构建仍有原有的大文件体积提示。
