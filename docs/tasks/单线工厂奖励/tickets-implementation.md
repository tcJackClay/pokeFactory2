# 本局补给券首切片实施记录

从 `ab8e961` 建立独立工作树。本切片只实现已定的补给券获得、存档与余额展示；未增加商品、价格、卡池或重抽动作。

存档升级为 v13，新增独立的 `runSupply`：挑战 ID、当前券数、最后入账战次。开始新挑战时券数归零，开发跳关以起始战次的前一场作为入账基线。每场工厂胜利在现有逐场原子战果提交中加 1 券；第七场同次提交补给券与整组 BP，两者分别记账。重复结算返回已提交的券数，不重复入账；跨七战组继续保留。败退时清空补给券，基地中主动结束挑战也清空；已取得的基地 BP 保留。

同版导入对缺失、非法、与挑战 ID 或战次不一致的补给券字段执行损坏存档保护。普通自动保存保留更新的入账进度，旧战斗快照和过期保存不能把已入账的券数回滚，也不能在败退后恢复旧券。v12 及更早的存档沿用明确的旧版提示、备份和重新开始路径。

战果页显示本局补给券余额；组末基地的继续挑战入口显示跨组余额。BP 的显示和钱包逻辑保持独立。静态测试覆盖逐胜和跨组累计、重复结算、旧保存、失败写盘重试、败退和主动结束清零、存档损坏保护。`npm run lint`、`npm test` 与 `npm run build` 通过。浏览器和实体手机实玩由后续 player/reviewer 执行；奖励卡与补给券消费仍待设计定稿。
