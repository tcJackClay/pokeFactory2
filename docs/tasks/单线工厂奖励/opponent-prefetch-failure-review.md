# 敌队预取失败只读调查

证据来自 `endturn-faint-runtime.md`：隔离手机模拟浏览器在第 1 战中完成玩家中毒濒死、强制换人，随后仍是可操作的 `BATTLE`；期间控制台出现一次 `Failed to generate valid opponent team.`，请求未见 HTTP 400 及以上。该日志**没有附 stage/context key/发生时刻**，不能据此称“下一战失败”，也不能把本次战斗判失败。该异常只在 `useFactoryFlow.ts` 的 `generateEnemyEncounter` 于 `buildFactoryPool` 返回少于 3 名成员时抛出；请求全 200 也可因本地筛选耗尽而出现。

`buildFactoryPool` 最多尝试 `3 × 25 = 75` 次。先从训练家参考 set、训练家物种提示取候选，候选为空才回退到选定单世代的全局随机池；随后还要满足已租借/己方/已选敌方物种不重复、能力值段/进化阶段、三人持有物不重复、详情处理成功等条件。代码只在“候选为空”时启用全局回退；若参考候选存在但反复命中已用道具，整次尝试直接 `continue`，可耗尽 75 次。训练家提示路径还需核查候选是否都在当前单世代内，不得为了避免失败而让敌队越过玩家所选世代。当前证据只能定位到**有效三人队未组成**，无法确定哪一种过滤/随机条件是本次主因。

预取与正式开战的保护边界如下：`startGame` 在六选三前就启动第 1 战预取，战间结果页才预取 `stage + 1`；因此没有 stage 的日志甚至无法确认是否为“下一对手”。`prefetchEnemy` 捕获异常、输出 `console.error`、清预取缓存并返回 `false`；`spawnEnemy` 若等待同 stage/key 预取失败，会再次调用 `generateEnemyEncounter`，因此一次后台失败不会直接中止当前战斗。开局六选三时，正式生成失败会回到 `FACTORY_SELECT` 供再次确认。战间 `nextFactoryStage` 在正式生成失败时恢复原战斗展示、保持原 stage/checkpoint，并返回 `false`，玩家可重新点“继续/换怪”；成功后才通过 `commitNextBattleStart` 固定下一战。由此风险是**后续战可能加载失败并要求重试**，而非这份第 1 战濒死续接已失败。若候选约束在某个世代/阶段持续不可满足，重试仍可能反复失败，属于发布阻断。

最短修复先加入有界结构化诊断：记录 stage、所选世代、训练家模板、参考/提示/全局来源、75 次尝试中按原因分类的拒绝数、最终人数和耗时；不记录用户隐私或整份队伍。将“可选候选”按物种与持有物唯一性过滤后再选；参考与训练家提示已经没有可用候选时，允许**同次尝试**落到当前单世代全局池，不因拿到不可用候选而阻断回退。仍守住三人、物种/持有物不重复、合法招式及世代约束；到上限时显示可重试的加载错误，保持战后节点和已结算结果，不静默生成不合规敌队。预取错误若被正式生成恢复，可作为低优先级诊断事件，避免玩家看到误导性的致命错误；正式生成失败则必须显式提示。

验收：纯函数/受控随机测试构造“参考池存在但道具均冲突”“训练家提示跨世代”“全局池可组成合法三人”“确实无合法三人”四例，断言前两例安全回退或明确拒绝，成功例三名均属选定世代且物种/持有物各不重复，失败例至多 75 次且错误包含分类统计。浏览器隔离存档重放：先强制预取失败再让正式生成成功，当前战斗与战间继续均可进入合法下一战；再使两次都失败，玩家停在原六选三/战后页、stage 和 BP/券不变，重试成功后只开一战且刷新仍一致。普通自然随机流程至少各选第 1、2、9 代打到第 2 战，保存 stage/key、拒绝统计、网络与截图；一次 `console.error` 本身不能替代后续战实测。
