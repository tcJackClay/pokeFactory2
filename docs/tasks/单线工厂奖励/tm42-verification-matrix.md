# Rogue 固定 50 TM 中其余 42 招的战斗验收矩阵

基线为项目 `577877a`、Rogue expansion 固定提交 `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014`，以及本地 `rogue-tm-effect-audit.md`。本表排除已另行计划的 TM11、15、18、24、28、32、35、44，共 42 招。当地审计显示其中 40 招有 PokeAPI 缓存和转换结果，TM17、33 缺缓存；**42 招均未因本表而获得“可发卡”资格**。Rogue 招式定义取本地 `output/rogue-expansion-reference/src/data/battle_moves.h`；本项目转换和结算分别见 `src/features/game/data/battle/index.ts`、`moveEffectTable.ts`、`src/features/game/hooks/useBattleController.ts` 和 `src/features/game/battle/engine`。项目有单打、九代互斥租借池，TM 可学性仍取固定 Rogue profile，不由 PokeAPI `machine` 推断。

每个断言都在无关特性、道具、天气、场地关闭的基线夹具上先验证，再对表中指定条件重复。固定随机序列分别覆盖效果发生和未发生；对比相同攻防、命中、随机伤害因子。每项至少断言玩家施招与敌方施招、PP 变化、命中/未命中或守住后的状态、战斗日志对应中文文案；状态技还要覆盖重复施放和状态已满时的失败结果。文中“阻断”均指该 TM 保持不进入奖励可发池，不因其他招式通过而放行。

## 最短分组实施顺序

1. **先修已证实的资料/转换阻断。** TM10、43 明确指定 `appliesTo:'user'` 且 `requiresHit`，用真实缓存 payload 的转换测试加命中/守住结果测试；TM17、33 先在固定版本内容库补齐 payload 与校验，冻结本地 SHA，再用同一加载链验效果。四项没过前都保持不可发。此批只改数据覆盖、`moveEffectTable.ts` 和所需测试，不碰整回合状态机。
2. **批量验证直接伤害、优先级、必中和暴击。** TM07、08、21、25、27、34、38、48，加上 TM01、03 的专用威力。纯引擎结果测试优先，逐项确认属性、类别、PP、免疫、守住。无复杂跨回合状态，能较早形成可用候选，但须完成真实资料链和手机实战后才开白名单。
3. **验证自身能力与命中后能力变化。** TM02、04、10、20、26、29、30、33、37、41、42、43、46、47、49。先验证转换出的 `appliesTo`、`chance`、`requiresHit`，再以固定随机断言实际等级与下一招伤害/行动序；特别把 TM10、43 视作真实 bug 修复而非走通测试即可。
4. **验证异常、反作用、畏缩与屏障。** TM05、13、14、16、19、22、23、39、40、45。把 0%/100% 注入随机边界、免疫、先后手、倒下后状态和换人清理都纳入结算测试。屏障效果要检查队伍侧状态的表达；如当前模型不能保持换人后的屏障，不得放行 TM19。
5. **验证天气与场地。** TM06、09、12、31、36、50 需要跨回合与双方视角；先补纯状态快照/计时测试，再做实际战斗的伤害、回复、命中与行动序断言。与另案 TM18 的雪天气实现一起回归，确保旧天气没有退化。

每批交付仅开放本批已逐项通过的固定 `TM 编号 → Rogue MOVE_* → 本项目 Move.name` 显式映射；Rogue 可学性、当前队伍能学且未掌握、资料 payload 完整、战斗效果准入、奖励检查点冻结和领取时再校验全部通过才发卡。任一字段未知、资料端点失败、转换结果不匹配、效果断言失败或手机实际战斗未验收时，该 TM 从候选池剔除；候选不足时保留奖励节点并给可重试反馈，不能凑卡或退回通用效果。四卡的 ITEM/TM 具体配比仍遵守已定设计，不在本计划发明。

## 验收证据与边界

- 静态证据保留每招源 `MOVE_*`、项目 ID、实际 payload 摘要、转换后 `MoveBattleData` 关键字段、Rogue 效果语义、断言结果和准入决定；`npm run typecheck`、相关 battle engine/数据/保存测试通过。项目 `buildMoveBattleDataFromPokeApiMove` 对未覆盖项默认 `effectId:'NONE'`，此默认值只有在该招确实没有特殊效果且结果断言通过时才可接受。
- 运行证据由 player 在 390×844 和 844×390 手机视口，至少一次自然奖励四选一领取 TM、选择合法队员并替换一招、进入下一战实际施放；对概率/免疫/到期等边界可用 DEV 辅助，记录其注入范围。逐招自动结果测试与代表性手机流程两者都要有，且不能把静态名称匹配或资料请求 200 当作通过。
- 当前记录中的 42 是“八项明显机制缺口以外”的盘点范围，不代表 42 项可直接实现或可发布。已知新增 TM10、43 目标错误，TM17、33 缺资料；其他行仍处于待验证状态，测试发现差异就维持失败封闭并形成小修复任务。
