# 回合末濒死续接手机模拟浏览器验收

2026-09-26 在主线提交 `c23989d`、本地预览 `4300` 上，用独立 `127.0.0.162` 来源的 Playwright Chromium 手机模拟器运行；没有操作用户原有标签或存档，也没有修改实现代码。Codex 侧栏浏览器不可用，本轮结果属于模拟浏览器验收。

先通过正常 UI 建立 v13 新档、选初遇伙伴、六选三并进入可操作的第 1 战，再从该真实 READY 存档制作隔离测试存档：前排喇叭芽 HP 改为 1 并设中毒，对手前排设为睡眠 10 回合，后备小磁怪与六尾保持原值，天气为无。测试存档经独立浏览器上下文载入后，画面确实显示喇叭芽 `1/110`、中毒和对手睡眠。[恢复后的测试画面](evidence/endturn-faint/fixture-restored-390.png)、[完整状态序列](evidence/endturn-faint/results.json)。此构造只用于精确触发回合末分支，不属于自然随机战斗。

通过 UI 实际选择一次“大晴天”后，对手因睡眠跳过行动，日志随后出现喇叭芽中毒伤害和“喇叭芽 倒下了！”。系统打开强制换人列表：濒死喇叭芽的出战按钮禁用，两只健康后备可选。[回合末与 320×568 画面](evidence/endturn-faint/after-round-320.png)、[强制换人列表](evidence/endturn-faint/forced-switch-ready-390.png)。点击小磁怪后，日志出现一次“你派出了 小磁怪！”，小磁怪以 `86/86` 成为前排并返回可操作战斗；原喇叭芽在队伍后排为 0 HP。[后备出场截图](evidence/endturn-faint/reserve-selected-390.png)。短时间稳定观察中仍为第 1 战 `BATTLE`、补给券 0，未见重复濒死提示、重复出场或误入胜负结算。[稳定状态](evidence/endturn-faint/stable-after-switch-390.png)。

320×568 画面中四招卡片均保留可读的属性角标，例如“草”“恶”“火”；页面没有横向溢出。测试期间有一次随机下一对手预取的控制台错误 `Failed to generate valid opponent team`，相关请求未返回 HTTP 400 及以上，当前战斗仍完成濒死续接。本轮仅覆盖玩家中毒回合末倒下且有后备；天气致死、双方同时倒下、无后备与刷新后的重复结算尚未做浏览器验收。
