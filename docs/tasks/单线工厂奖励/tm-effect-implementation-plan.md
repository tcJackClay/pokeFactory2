# 50 TM 的八项战斗效果实施与验收计划

基线：本项目 `7c39f60`，Rogue expansion `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014`。八项是 `rogue-tm-effect-audit.md` 已确认的明显缺口，不代表另外 42 招已通过实战。完成下列切片前，这八招不得进入“可发放且效果正确”的 TM 池；不能以普通伤害、普通状态招式或成功转换 PokeAPI JSON 代替效果实现。每个切片先落纯结算及有结果断言的测试，再接控制器与界面，最后由 player 手机试玩。

切片顺序按共用依赖安排：先天气独立闭环，再分侧计时，再统一入场管线和陷阱，继而 pivot 复用入场，最后处理跨回合锁定。每个切片单独交审，避免同时改写 `useBattleController.ts` 行动时序。原型证据：Rogue `src/data/battle_moves.h` 的八个 `MOVE_*` 表项；`data/battle_scripts_1.s` 的 `BattleScript_EffectSolarBeam`、`EffectHitEscape`、`EffectRampage`；`src/battle_script_commands.c` 的 `Cmd_settailwind`、`Cmd_settoxicspikes`、`Cmd_setstealthrock`、`BS_SetSnow`；`src/battle_util.c` 的入场陷阱、顺风倒计时、雪防御判定。原型还包含其他招式、特性和道具互动；遇到项目未支持的互动应记录为明确未覆盖，不能声明与原型完整一致。

当前保存 `BattleResumeSnapshot` 写在每场开战检查点，`commitFactoryBattleStart` 初始化天气和场地。项目须确认刷新战斗的实际回滚语义；如仍从开战重打，战中上述状态仅保存在内存，并在刷新后回到开战无状态，此行为须明示且验收。若允许回合中续玩，则需在 `saveManager.ts` 同版 schema 中序列化并严格校验双方陷阱、顺风计时和成员锁定，原子写入每回合快照；不能出现界面保留效果而行动次序丢失的半恢复。新战开始、胜负结算及放弃挑战均清战场状态；一组七场和跨组也不继承，但队伍成员及其 PP/持有物遵循现有工厂规则。用户已允许旧版本存档不兼容，不需为旧 schema 加迁移。

## 每批必须通过的结果断言

1. **天气**：固定相同攻击、防御与随机数，雪中冰系承受物理伤害严格小于无天气，特殊伤害不获防御加成；非冰系雪后回合 HP 不变；冰雹来源仍按旧规则掉血；五次回合末后 `weather === 'none'`；雪中 `Blizzard` 命中率与 `Slush Rush`/`Snow Cloak` 和预期一致。不能只断言 `weather === 'snow'`。
2. **顺风**：速度 50 对 80，速度 50 一侧有顺风后先手，四次回合末后恢复后手；换上同侧后备仍先手；对手侧顺风不增强玩家；先制招式优先级、戏法空间反转优先于/作用于最终速度；重复使用不延长到第五回合。
3. **隐形岩**：100 HP 的 2 倍岩石弱点成员入场损失 25 HP，0.5 倍成员损失 6 或 7 HP 需按引擎统一取整规则确定并断言；第二次施放层数仍为 1；主动/强制/敌方换人各只结算一次；入场打倒成员时后备接续且不会让已倒下成员再行动。
4. **毒菱**：第一层入场为普通中毒，第二层为剧毒，第三次施放不增加；接地毒属性入场清层数为 0；钢/飞行/漂浮和已有异常者不被重复上毒；岩石先击倒则毒菱不对该成员生效。双方各自一侧陷阱独立。
5. **Pivot**：急速折返命中且有后备时，伤害记录与对手 HP 正确，换入成员承受对手尚未执行的行动；伏特替换打地面免疫者、被守住、未命中、无存活后备、施招者倒下时均无换人；敌方使用时玩家不能替敌人选成员；全程 PP 减一次。
6. **日光刃**：非晴天第一回合目标 HP 不变、PP 减一，第二回合目标 HP 下降且 PP 不再减；晴天第一回合直接伤害；雨/沙/雪时伤害低于相同属性条件的无天气；蓄力后换人或倒下再上场不自动释放。
7. **逆鳞**：固定随机种子分别使其持续 2 与 3 回合；锁定中改招和主动换人无效，PP 在整段只减一，结束后成员有混乱状态；受阻后的计时与 Rogue 对照用例一致；退出战斗和重新入场无残留锁定。
8. **状态边界**：每项分别在玩家和敌方施放测试；同一战内换人仍保留天气、顺风、陷阱，成员蓄力/连发清除；新战开始均清空场地类状态；刷新要么完整回到开战快照，要么完整恢复回合快照，不得出现重复 PP、重复伤害或半残状态。

静态门槛：逐招构造 PokeAPI payload 验证 `buildMoveBattleDataFromPokeApiMove` 得到专用效果标识，固定 TM 白名单仅允许已通过对应结果测试与运行验收的招式；`npm run typecheck`、项目现有 battle engine 单测及所涉保存校验测试通过。运行门槛由 player 在 390×844 与 844×390 浏览器实际使用双方招式：可选招式/强制选招、伤害与状态文案、换人列表、出场伤害、回合计数、刷新后结果均截图或录像留证；至少走完一次含对应招式的三战奖励到下一战，检查不会影响工厂结算与存档。DEV 注入可构造边界，但不能代替自然流程的奖励领取和战斗验收。

## 审查时先解决的具体边界

- `useBattleController.ts` 目前普通换人直接交敌方行动，击倒补位和敌方主动换人又各有入口；先统一入场结算和行动交接，再接 pivot。不要直接在造成伤害后调用 `switchPokemon`。
- `resolveEndTurn` 只知道单个天气/场地及成员，没有双方侧状态；顺风/陷阱需要独立的战斗级状态，不能写进 `FieldState[]` 或每只成员的状态图。切片 2 与 3 可共用 `BattleSideState` 数据结构，但提交仍分开。
- `snowscape` 当前错误映射为 `hail`，`Weather` 与 `saveManager` 均只接受旧值；需连同天气伤害、命中、速度、技能受天气修正一起改，避免只改映射字面值。
- `uproar` 已有强制选招和持续回合，但其禁止换人、PP 和中断路径与逆鳞并非完全同一规则；抽公共“强制行动选择”接口，保留各招自身计时与收尾。
- 八项中任一专用效果缺失时，奖励池过滤应失败封闭并给审计清单；不得静默退回普通攻击或空状态技。
