# Rogue 工厂模式设计选项

**历史草案，已被用户最新决定覆盖。** 首版改为一条工厂主线，在第 3、6 胜后加入四选一奖励卡和仅本局有效的补给券；此前双模式、旧第 4/7 战前方案及文末券数值均未获批准。现行设计依据为《docs/公开版规则定稿.md》和《docs/tasks/单线工厂奖励/design.md》；下文仅作旧方案与代码风险参考。

本页只读核对《宝可梦对战工厂_项目设计框架_v1.md》§4.4–4.5、当前代码与本地《对战工厂_参考索引.md》定位的 Battle Factory 参考实现。文末是**供审阅的最小玩法提案，尚未获用户批准**；不得据此改动 Classic、发放 BP 或开放商店。

## 必须隔离的状态

1. **运行身份与纪录**：模式选择、正在进行的 run、组号/战次/连胜、最高纪录和组结算必须带模式；不能把 Rogue 胜场写成 Classic 纪录或让模式切换复用对方检查点。
2. **局内奖励**：奖励候选、已选择、重抽次数、待完成的学招式/进化/换队员操作，以及奖励页阶段须归属 Rogue run 并可刷新恢复。Classic 无 `REWARD` 路径。
3. **局内资源与基地 BP**：任何 Rogue 购物或重抽的货币必须标明来源、用途和清零时机。若与基地 BP 共用，需单独批准并解释与每组 3 BP 的比例；不能沿用旧 `50 + 50n` 价格。Classic 原型 BP 发放条件保持独立。
4. **战斗特殊状态**：玩家/对手的特殊机制解锁与使用次数、特殊首领标记、背包道具，须按 mode 检查可用性并在同一 run 恢复；不能因 Rogue 奖励把 Classic 的后续战斗带入扩展效果。
5. **世代与队伍来源**：用户已定九个世代互斥池。若 Rogue 共用所选世代，奖励宝可梦也须从该池取；如果允许突破世代或带入培育队，则应独立定稿并明确纪录不与 Classic 比较。

## 可审阅的最小玩法提案，未批准

以下方案的数字、节点和限制全是**设计提案**。它先让玩家体验 Rogue 的“租借 → 战斗 → 换怪 → 额外选择 → 下一战”，并使 Classic 继续使用已定规则；用户可以逐项改动。

1. **入口与挑战**：在基地选 Rogue 后开一条独立标记的 run；同一存档一次只保留一条进行中 run，进行中不切换模式。Rogue 暂共用设置里唯一选定的工厂世代、六选三与七战一组，前六胜仍可换一只，第七胜返回组结算。Classic 纪录与 Rogue 纪录分别展示。
2. **奖励卡**：沿用现有组内第 4、7 战前两个节点，放在可选换怪之后、下一战之前；每节点四选一。首个可玩版本只开放现有 ITEM 与 TM 卡，ITEM 限下述四种普通补给品，限制一张生效，暂不开放增加队员、进化、特殊机制道具或队伍容量，保持三只租借的读局重点。抽卡结果和“已领取”须随 Rogue run 保存，刷新不会重抽或重复领取。
3. **局内商店**：在同两个节点提供一个独立的“补给”入口。提案商品限定为现有 `ALL_ITEMS` 中的 `potion`（恢复 50 HP）、`heal`（完全恢复 HP）、`battle_atk`（下一次攻击伤害提升 50%）和 `battle_def`（一回合减伤 30%）四项；这些效果来自当前物品定义，商品开放与价格仍只是提案。提案使用仅 Rogue run 有效的补给券：每胜获得 1 券，每件 2 券；每节点限购 1 件，离开 run 清零。特殊机制道具和队伍容量许可不在这张提案商品表。首个版本不启用付费重抽，避免沿用 50 BP 旧公式。
4. **特殊机制与事件**：首个可玩版本只保留已实现的战斗特殊机制入口，但不因选 Rogue 自动赠送使用资格；解锁、物品和次数另由用户定稿后开启。随机事件和普通战捕捉也先不开放，避免在规则未定时改写工厂胜负与收集来源。
5. **经济与结算**：提案将 Rogue 补给券与基地 BP 完全分开；Rogue 组末只记录独立成绩，暂不发原型 BP。是否最终给 Rogue BP 须用户决定，不能把 Classic 的 `FACTORY_SINGLES_BP` 直接复用为双模式共同奖励。失败丢弃本 run 补给券，已有基地 BP 不因 Rogue 败退变化。

上述提案只是一个可审阅的最小切片；特殊机制解锁、随机事件、捕捉和 Rogue 组末 BP 仍需另行决定，不能称完整 Rogue 或公开版已可玩。用户确定规则后再拆实现和验收；尤其要验证 Classic 无奖励卡、两模式存档与纪录隔离、Rogue 奖励页刷新恢复、购买次数及 BP 不串用。
