# 基地钱包持久化旧规则运行基线

**已被 2026-09-26 的规则更正取代：公开版恢复原型 Battle Points，整组七战结束后才发放。** 本文记录的是此前“每场胜负立即入账”实现的实际运行情况，仅供识别和回归旧行为；不得作为当前规则的通过结论。新规则的运行验收见[组末 BP 结算记录](../组末BP结算/runtime.md)。

日期：2026-09-26。基线提交 `13a7a85`；验收时工作树含钱包、版权页、横屏布局等未提交改动，本记录对应运行中的工作树版本。前端 Vite `4300`、Go 服务 `3001`。以独立 Chrome 测试上下文访问 `http://127.0.0.4:4300/`，没有读取、覆盖或清空用户 `127.0.0.1` 的存档。使用桌面浏览器视口模拟手机，实体手机未测。

## 正式新存档失败路径

`390×844` 从新存档基地开始挑战、六选三、进入可操作战斗，点击「逃跑」后再次确认失败。租借池三次可复现加载分别约 10.1、10.2、12.9 秒；对应观察到 148、126、125 个本地 `/api/pokeapi/*` 成功响应。此前一次脚本等待 `checkbox` 达到 120 秒超时，而当前租借卡实际为 `button`，并非游戏加载耗尽 120 秒；更正选择器后流程正常。

战前钱包 `balance=0`、`revision=1`；失败结果页显示「获得代币：+1」，顶部余额显示 1。存档变为 `balance=1`、`revision=2`、`settledThrough=1`，`lastSettlement` 明确记录 `stage=1`、`result=LOSS`、`amount=1`。返回基地后、刷新后仍为同一余额与结算记录。再开始新局，六张租借卡正常出现，余额仍为 1，生成新的 `runId`，`settledThrough` 重置为 0。证据：[失败前画面](evidence/390-loss-before.png)、[失败结果](evidence/390-loss-after.png)、[基地余额](evidence/390-loss-base.png)、[刷新后基地](evidence/390-loss-base-refresh.png)、[新局租借](evidence/390-next-run-rentals.png)、[状态记录](evidence/loss-persistence.json)。

## 胜利与故障恢复

使用上述失败后保留余额 1 的隔离存档开启新局、六选三进入战斗，再启用开发面板的 `Win` 强制触发胜利结算。**这是 DEV 胜利结算路径，未证明普通出招自然取胜的完整体验。** 结算前余额 1、`revision=3`；结果页显示「获得代币：+4」，余额变为 5、`revision=4`，`lastSettlement` 为 `stage=1`、`result=WIN`、`amount=4`。刷新后仍为 5，没有再次入账。[胜利状态记录](evidence/dev-win-observation.json)、[结果页截图](evidence/390-dev-win-result.png)。

在另一条独立 DEV 胜利测试中，于结算写入时一次性模拟浏览器存储配额错误。写入失败后余额保持 1、结算序号仍为 0，画面明确提示「结算未能保存，代币尚未到账。请重试。」；同标签刷新后仍显示重试入口。点击「重试结算」后余额仅增加一次到 5、结算序号变为 1。关闭该标签并用已保存的浏览器状态重新打开时，余额仍为 1、结算未发生，战斗检查点可重进；重新触发 DEV 胜利后得到一次 +4，余额为 5。新标签没有直接显示重试提示，需要重打该战斗。证据：[失败提示](evidence/390-settlement-write-failed.png)、[刷新后提示](evidence/390-settlement-after-refresh.png)、[重试后结果](evidence/390-settlement-after-retry.png)、[同标签状态记录](evidence/write-failure-observation.json)、[关闭再打开状态](evidence/close-reopen-observation.json)。

## 手机尺寸与错误

用余额为 1 的同一隔离存档在 `320×568` 和 `844×390` 检查基地：余额可见，开始挑战按钮可触达，页面尺寸与视口一致、没有横向溢出。[320×568 基地](evidence/320x568-base-wallet1.png)、[844×390 基地](evidence/844x390-base-wallet1.png)。`390×844` 的结果页和基地截图见上。新一轮完整加载中浏览器控制台未见脚本异常；此前版权页测试发现的 `/favicon.ico` 404 在修正后完整刷新复测中未再出现。

本轮尚未验证普通出招自然取胜、七战组结算、导出再导入、旧版存档迁移、不同战次连续入账和实体手机触控。故障注入只覆盖浏览器单键写入失败，不代表所有磁盘、浏览器隐私模式或服务端故障。上述逐场入账现象属于**已废弃规则的基线证据**；新规则要求整组七战结束才发放 Battle Points，需重新设计并试玩验收。
