# 基地钱包持久化需求

## 玩家目标

玩家完成整组七战并获胜后，按本地参考工厂**单打** Battle Points 表领取组奖励；回到基地能看到同一个持久 BP 余额。前六场胜利不加 BP，中途败退 0 BP。刷新、继续挑战、开始新局或导出再导入存档后，已获得的 BP 仍在，重复进入组结算不会重复领取。

## 依据与范围

- 用户最新决定覆盖此前“每场胜负结算后立即入账”：仅七战整组获胜后按参考工厂单打表发 BP；第 1、2 组各 3 BP，之后按 `reference/pokeemerald-expansion/src/frontier_util.c` 的 `sBattlePointAwards[FRONTIER_FACILITY_FACTORY][FRONTIER_MODE_SINGLES]`；击败工厂首领额外 10 BP；败退 0 BP。
- 本地固定参考提交 `ca17c6a3d40a` 的 `BattleFactoryBattleRoom/scripts.inc` 在第七胜标记成功，`BattleFactoryLobby/scripts.inc` 仅成功分支调用 `frontier_givepoints`，失败分支无发放；`frontier_util.c` 的 `GiveBattlePoints` 读取上述表并加首领奖励。
- 当前钱包持久化、写入失败反馈和幂等基础可以复用。先前逐场入账的触发点、胜负奖励公式与结果页文案均须改；旧任务的逐场试玩证据仅证明旧实现，不能作为新发放规则验收。
- 商店商品、消费和额外的失败成长渠道不在本轮定稿。用户不要求兼容过往存档：旧版可重置或拒绝导入，但必须清楚提示；旧代币不能转换成 BP。

## 完成条件

1. 前六场胜利以及任一中途败退均不发 BP；第七场胜利完成整组后，按工厂单打表向基地钱包入账一次。第 1、2 组各 3 BP；后续组别逐项按完整参考表计算；击败工厂首领时另加 10 BP。组结算页与基地余额一致。
2. 同一组重复进入结算、刷新恢复不会重复入账；不同完成的组别分别入账，且不会因单场结算误发。
3. 新局不清空新版本的钱包；新版本导出导入保留 BP。旧版存档可重置或拒绝导入，但必须给玩家明确提示，不把旧代币算作 BP。
4. 本地保存失败时不给出已到账的假反馈，玩家能重试或恢复。
5. 静态验证与手机尺寸真实运行验收均有记录，特别覆盖第 1、2、3 组、首领胜利、任一中途败退和组末重复结算。

原 [plan.md](plan.md) 按已被覆盖的逐场入账规则编写，只能复用其中钱包持久化与去重设计；组末发放技术路径应以 [组末 BP 结算需求](../组末BP结算/prd.md) 为新依据重新制定。
