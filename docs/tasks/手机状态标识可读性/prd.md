# PRD：手机状态标识可读性

orchestrator 拥有。依据：用户要求手机浏览器体验、完整发布打磨；GDD 手机适配要求；`基地事件界面修整/runtime.md` 已记录的一般属性白底不可辨及英文320顶部Round截断。属于既有信息的可读性修复，不新增玩法、数值或资源。

## 任务边界

- 独立 `codex/mobile-status-readability`，从已验主线建立。不得改正在实玩的九道具工作树。
- 只处理共享属性图标的浅底可辨性及顶部BP/轮次/连胜面板的小屏信息布局。architect 先核消费方，选最小影响面；不默认改全站属性配色。
- 禁止战斗控制器、builder、存档、事件交易、商品、派遣资格改动。不改现有指标含义/取值，图标不得换成另一属性。

## Feature Spec

1. 地区派遣中，关都既有一般/水/草三类要求都能看出各自图标。一般图标不能因白底与白色mask成为空白；同一共享图标在现有深浅底和属性徽标中保持可辨，不破坏显式颜色覆盖。
2. 手机320宽度下，顶部BP、Round、Streak及实际数值均可完整辨认，不靠hover/title补齐被省略的信息。390竖屏与844横屏保持布局可读，不溢出或遮盖其他内容。
3. 简中/繁中/英文标签使用对应语言；现有BP值、组内战次和连胜含义不变。若原繁中标签直接复用简中，本片仅为该面板提供正确繁中字形，不扩成全站翻译。
4. 保持已有导航和点击目标可达。允许局部自适应排布，不能靠将文字缩到不可读或隐藏指标解决宽度。

## Edge Cases

- 普通新档0 BP/0连胜，组内1/7和7/7，钱包合法上限9999、较长连胜值均须检查。不得仅用三项全0证明大数可读。
- 当前图标使用了显式color、CSS currentColor、style覆盖等入口，调整前核清差异，避免“白徽标上的黑图标”被统一改成白色。
- 现有18属性资产与语义保持；不改水/火等素材映射。不需要重画美术或新增资产。
- CSS影响全站时，必须检查战斗招式、租借/图鉴属性徽标等实际消费方；不能用事件单页通过替代共享影响面验证。

## 验收

- 独立静态审计及串行四门禁，明确业务改动只落批准显示路径。低风险样式修改无需写镜像实现的单元测试。
- 最终冻结SHA，真实Go+Vite实玩；简/繁/英 × 320×568、390×844、844×390可读，顶部标签/大值和关都图标有截图与实际页面证据。
- 标明自然新档与注入大值/指定成员的受控对照。至少实际进入基地→事件和工厂租借/战斗消费方，无横向溢出、按钮被遮挡或非预期控制台错误。
- 这是模拟浏览器显示修复，不能声称实体Android、全站无障碍或公开发布已通过。
