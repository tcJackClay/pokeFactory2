# PRD：TM 固定正文

orchestrator 拥有。来源：用户指定 Rogue expansion 技能配置、公开版规则定稿、工厂内容准入 design 与 `tm50固定正文与档位提案.md`。固定版本 `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014`，普通 profile、普通招式表、该版本有效 GEN_LATEST 配置；名单为已确定的50项。

## 玩家结果与边界

让这50项招式的显示及战斗读取正文有可追溯、可复现的固定来源，避免在线数据版本与已指定参考混用。正文存在与效果正确、售卖批准分别验收。本任务不批准任何价格，不默认上架，不修改兼容性名单，不改变六件商店交易。

先由 architect 核对已合入的固定TM资格数据、既有 move builder 与九道具元数据方案，确定最小文件边界和下游效果验收依赖。**当前仅授权写 plan/context，不编辑业务代码。** 九道具任务拥有正文元数据及战斗控制器；其后先串行修复高速旋转，再实施本任务，不同时改共享 builder。

## Feature Spec

1. 为全部50项生成固定正文与来源记录：类型、类别、基础威力语义、命中语义、基础 PP、优先级、目标及支持效果所需的参考信息。宏与条件按有效配置求值，未知表达式/重复/漏项不得静默采用默认值。
2. 目标/必中/动态威力必须保留语义：源0命中不能直接成为0%命中；自身与场地无需对敌命中，攻击必中仍遵守保护/免疫；报恩源威力1是动态占位。用户尚未决定租借亲密度口径，保留待决，不能借数据接线把全队设255。
3. 构造后的真实成员招式由生产读取链消费上述正文；显示与引擎使用相同数值，双方一致，特殊来源/形态不能错映射。保留九道具已批准 makesContact 等固定元数据以及当前轮次/PP/场地契约。具体接线点由 architect 研究，若需新机制必须回到上游设计。
4. 不把尚未实现的效果伪装成可用：逐项关联已知执行器/测试与缺口，保留正文证据、战斗证据、价格与资格四项分离。状态仍 pending 的项目不得因为有JSON或通过构建变为 saleEligible。
5. 数据生成可重跑，记录源提交、原始文件摘要、映射/配置及生成摘要；只核固定50项，不重做已验1076身份/9981配对模块、不扩大到全部在线招式。

## Edge Cases 与验收

- 离线/正文网络失败时，固定50项已知正文不能退回不同版本数值；未知项目不能冒名匹配到其中一项。实际资源链及故障行为由 plan 明确。
- 顺风15PP、打雷110威力、电磁波90命中、逆鳞120威力10PP、戏法空间-7优先级须有具体断言；配置分支和动态/必中语义不能用生成文件自比验证。
- 独立auditor对照原始固定源核查50项；实现者四门禁。生产 builder 的两侧正文与中文/英文显示至少有真实浏览器代表例，精确50项数据由独立来源对照覆盖；这不是50项全部效果实玩。
- 新基线不得回退永久收藏、状态命中和九道具结果。最终 player 在冻结代码上运行，真实Go+Vite，模拟视口与受控招式条件如实说明；不宣称实体Android或生产通过。

报价/报恩行为待决不妨碍目前的只读调研；后续实现授权和逐效果任务顺序由 orchestrator 另发。
