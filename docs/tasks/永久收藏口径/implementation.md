## 证据边界与后续缺口

1. 永久来源保存不等于完整事件战断点。既有事件战的队伍/背包/回合没有独立恢复结构，本任务只保证成功永久获得离场与刷新/同版导入保留。
2. **自然新档球来源缺口经全src核对**：
   - 球定义：`uiAppConstants.ts`的pokeball、greatball、ultraball、masterball，isBall=true，倍率分别为1/1.5/2/255。
   - 新档背包初始化来自工厂checkpoint的inventoryItemIds或空数组；正常工厂开局与DEV开局均清空背包。
   - 所有现有增加背包入口：派遣item/事件胜利走成长道具池（protein、iron、calcium、zinc_item、carbos、hp_up）；旧useRewardFlow候选池亦没有球；当前六件交换货架只有持有物/进化物，DEV面板没有送球。
   - 加入事件取背包首个isBall，收藏提交后扣1；事件战入场要求有球，捕捉选定球成功提交或正常概率失败后扣1。
   - 因此R7需要明确标注受控球/队伍/就绪派遣夹具，不能称自然新档已闭环。未擅自赠球、改消耗或增加商品；后续基地/事件可达性需单独补规则。
3. 原捕捉公式统一上限0.95，大师球虽文案声称绝不失败也受上限影响。本任务按保留数值决定未改，这是既有文案/数值不一致，已报告orchestrator。
4. 用户实际设备仍优先Android Chrome；模拟Chromium触控不构成实体手机验收。

## 审计重点

- 所有保存主档的入口均经来源归一；显式导入不能与当前档混合来源。
- 捕捉回调在耗球前；失败/重复必须取消简单轮次，不能跌入enemy action。
- 同一派遣startedAt唯一键重复不得发第二只；新派遣不同startedAt不应被旧完成态阻止。
- 保留上游当前场地与状态命中修复，控制器diff只涉及捕捉提交和取消处理。
