## 功能规格

### F1：目标与初始状态

在玩家或敌方已通过既有出招前置检查、选定合法状态招式时生效。参与者、招式、目标、命中/闪避等级、特性、当前持有物、保护/替身与天气均取当前行动的有效状态；不因异步日志使用上一成员或上一战斗的数据。来源 D1、D3、D4。

### F2：对敌状态招式的命中

对敌宝可梦施放、具有数值命中率的状态招式，与已有共用命中规则一致判定。没有直接伤害不代表必中。命中后继续遵循该招的能力等级边界、异常免疫与适用条件；未命中显示未命中反馈，本次目标能力/异常不变，依赖该次命中的其他效果不发生，不因本次未命中消费白色香草。玩家和敌方对称。来源 D1、D2。

一次合法出招消耗一次 PP，未命中仍完成一次行动，不重放、不多扣 PP、不额外产生回合末结算。“主效果必定发生”只指通过命中和适用性检查后的效果。来源 D1。

### F3：共用命中规则与例外

沿用既有命中/闪避等级、已接入特性、天气及道具修正，普通数值 100 仍可能受修正影响；已接入的无防守与毒属性使用者的剧毒必中语义保持。无命中率 `null` 或明确忽略命中检查的招式不掷普通命中。项目数值 `accuracy=0` 不能直接套用参考 C 的“0 表示不计算”定义。必中不代表穿透保护、替身或免疫。来源 D2。

### F4：自用、队伍、天气与场地

自用提升/治疗/保护/替身及实际作用目标为队伍或场地的状态技，不因对手闪避、保护或替身新增失败，保持自身已有条件与失败结果。按真实目标及效果语义区分，不按状态技一类全跳过或全掷命中。冥想与求雨作为代表；具体目标映射须由 architect 读真实数据后在计划中明确。来源 D3。

目标为 `user/user-field`、实际天气/场地/空间和 `opponents-field` 陷阱不被当前对手保护/替身误挡。`all-pokemon` 不自动免检：黑雾是全场清等级、参考明确忽略保护/替身；摇晃舞对个体施加混乱，按个体适用性及命中检查，不能仅因该目标标签跳过。来源 D3 目标分类表。

对敌普通状态技被既有保护或替身挡下时，保持一致的阻挡结果，目标效果与依赖该效果的香草不触发；已有明确绕过例外保留，不泛化全部声音/全场招式。来源 D4。

### F5：白色香草与终态

招式实际降级后，任一能力低于初始值 0 时香草恢复全部负等级为 0，正等级不变，一次消费并记录；自身下降也适用。未命中、阻挡或没有实际负等级时不因本次行为消费香草。当前持有物消费不更改本局装备基准，下一战按基准返还。王者盾牌接触自降与自身蛮力等已修路径不回退。来源 D5、现行规则定稿。

### F6：行动间 PP 与完整回合检查点

2026-10-13 基线 player 的 `docs/tasks/手机资源基线/pp-probe/` 已确认：玩家飞翔命中后 PP 15→14，敌方未命中且回合结束后回滚为 15，刷新仍为 15；敌方命中对照保持 14。此缺陷属于 F1/F2 已要求的“一次合法行动扣一次 PP、当前有效状态和完整检查点一致”，纳入本任务串行修复。

一方完成行动后，另一方的未命中/阻挡收尾和回合末恢复不得把前者已经发生的 PP、HP、持有物与能力变化覆盖为旧快照。整轮结束和刷新恢复必须保留该轮的合法结果；不能以跳过保存、再扣一次 PP、删除回合末恢复等方式遮蔽回滚。不借本次修复新增飞翔的两回合机制。

## 边界情况

- 未命中负例从无既存负能力等级的正常快照开始，避免人为旧负等级混淆香草触发原因。
- 合法一次行动只产生一种符合实际原因的终态；本任务不重排所有失败提示的优先级。
- 保护/替身、自用/场地、无命中率、必中、数值命中分别验证；不能只移动状态分支而遗漏目标语义。
- 日志结束与完整回合保存后再读结果；刷新从最近完整检查点恢复，不能因恢复重复扣 PP、消费道具或重放一轮。
- 不改既有伤害招式概率和主效果/次效果概率语义；共用函数变化须提供伤害招式回归。

## 验收条件

- AC1：双方分别有命中/未命中状态技证据；未命中目标不变、香草不消费，PP 各只扣一次，轮次不增加。
- AC2：普通数值 100 受已有命中等级修正，数值边界可静态确定；现有无防守、毒系剧毒、null 命中例外保持，仍尊重适用性。
- AC3：冥想与求雨等代表自用/场地技在对手闪避/保护/替身下正确生效；代表既有无效条件未被绕过。
- AC4：普通对敌状态技被保护/替身阻断，无目标变化或香草消费；既有例外有针对性回归。
- AC5：羽毛舞命中→负等级→香草恢复/消费；未命中→原状态保持。自身下降、王者盾牌接触路径与下战返还有对应回归证据。
- AC6：刷新/完整回合保存、双方顺序与攻击招式不回退；四项静态门禁通过，独立 auditor PASS。
- AC7：最终代码真实 Go+Vite 的浏览器 UI 验证，指定 390×844 为主要视口并检查 320×568/844×390 关键反馈；标明受控夹具与真实操作，不使用 DEV Win。实体手机优先 Android Chrome，未有设备证据时不得标为实体通过。

- AC8：以已确认夹具复验“我方飞翔命中→敌方未命中→剩饭恢复”和敌方命中对照；两者本轮 PP 只扣一次，回合末及刷新后保持，相关 HP/道具/等级结果不回滚。受控证据不能替代自然长局；增加针对旧快照覆盖的有意义静态回归。

每条验证方式、状态字段与证据位置由 architect 写进 plan；player 只负责运行和证据，不改实现。
