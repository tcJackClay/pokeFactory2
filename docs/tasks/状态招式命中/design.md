# 状态招式命中规则核对

日期：2026-10-13。designer 产物。用途：给本任务 PRD 提供玩家结果；这是已确认缺陷的修复口径，不新增概率、世代设置或战斗机制。

## 依据与边界

- 用户已授权继续完善并逐项验证。现行工厂规则及白色香草以 `docs/公开版规则定稿.md`、`docs/tasks/奖励商店/prd.md` F6 为准。
- 项目当前共用命中规则：`src/features/game/battle/engine/resolveAccuracy.ts` 的 `getResolvedMoveAccuracy` / `resolveAccuracy`；命中资料解释：`src/features/game/data/battle/index.ts` 的 `getMoveAccuracy`。本任务让对敌状态招式使用这套既有口径，不另设状态招式概率表。
- 固定参考为 Rogue expansion `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014`，本地 `output/rogue-expansion-reference`。`src/battle_script_commands.c` 的 `Cmd_accuracycheck`（1816 起）、`AccuracyCalcHelper`（1596 起）将普通命中、必中条件与保护分开；`data/battle_scripts_1.s` 的 `BattleScript_EffectStatDown`（3969 起）和 `BattleScript_EffectSleep`（3570 起）明确对敌状态效果需要命中，自用能力提升的 `BattleScript_EffectStatUp`（3915 起）不对对手掷命中。
- 白色香草参考沿用本项目既定的 `reference/pokeemerald-expansion/src/battle_hold_effects.c` 的 `RestoreWhiteHerbStats`（149 起），及 `data/battle_scripts_1.s` 的 `BattleScript_WhiteHerbRet`。它恢复低于初始值的能力等级，实际恢复才消费，不限下降来自对手。
- 项目命中实现不等于已覆盖参考的全部特性、特殊招式和世代差异。本任务不把参考中尚未接入的特殊条件顺手认定为已实现。遇到与既有规则冲突的招式逐项记录，不能用通用概率猜测补齐。

## 玩家可见规则

### D1：对敌状态招式

有数值命中率且作用于敌方宝可梦的状态招式，在未被既有保护、替身或招式自身适用条件阻止时，按当前共用命中规则决定是否命中。玩家与敌方同一口径；不能因为招式没有直接伤害而自动命中。

- 命中时，继续按招式本来的目标、能力等级边界、异常免疫和作用条件结算，不能把“命中”当作无视免疫。
- 未命中时，显示未命中的结果，该次招式不改变目标能力或异常，不产生本次依赖命中的用户/目标效果，不触发由该次下降引起的白色香草消费。
- 一次合法出招消耗一次该招 PP并完成一次行动；未命中仍消耗 PP，不重放或补偿一回合。原有无法行动、无 PP 等前置判定不在本任务改写。
- “主效果必定发生”指通过命中和适用性检查后的效果，例如羽毛舞命中后攻击下降；它不等于这招永必中。原始资料中的 `secondaryEffectChance=0` 也不能把主能力效果误解释成永远不发生。

### D2：数值命中与必中条件

沿用 `resolveAccuracy` 的现有命中/闪避等级、已接入的特性、天气和道具修正；这次不调整倍率。100 命中率的普通招式仍可能因这些修正未命中。项目已有的无防守与毒属性使用者的剧毒必中条件继续适用，不能因加入状态技命中步骤而失效；必中仍不等于穿透保护、替身或异常免疫。

项目中无命中率（`null`）或明确忽略命中检查的招式不掷普通命中；保持原有效果适用条件。注意：参考 C 数据的 `.accuracy = 0` 是“不做普通命中计算”的标记，项目 `Move.accuracy = 0` 在既有数值规则中为零命中率；两者不是可直接复制的同一种数据。不能把项目全部数值 0 统一改成必中，真实数据适配由 architect 单独核对。

### D3：自用、己方队伍和场地招式

自用能力提升、治疗、保护、替身，以及实际目标为队伍/天气/场地的招式，不因对手闪避等级、对手保护或替身而新增失败。它们保留自身已定的成功/失败条件，例如能力达到上限、替身所需 HP、重复天气/场地或保护连续使用的既有处理。

代表参考：`src/data/battle_moves.h` 中冥想 `MOVE_CALM_MIND`（6195 起）目标自身、忽略保护；求雨 `MOVE_RAIN_DANCE`（4280 起）目标全场、忽略保护。对敌羽毛舞 `MOVE_FEATHER_DANCE`（5312 起）则有数值命中率与敌方目标。具体归类按真实招式目标与效果语义，不能仅按“状态招式”一类全跳过或全增加掷骰。

本任务同时纠正与命中共用路径直接相关的自方/场地招式被对手保护、替身误拦截，分类结果如下：

| 实际作用范围 | 玩家结果 | 固定参考 |
| --- | --- | --- |
| 自身或己方队伍（项目可能标作 `user` / `user-field`） | 冥想、顺风等不对敌方进行命中或保护/替身判断；仍检查各自效果条件 | `MOVE_CALM_MIND`、`MOVE_TAILWIND`（6526 起）；`BattleScript_EffectStatUp`、`BattleScript_EffectTailwind` |
| 整个战场的天气、场地、空间 | 求雨、戏法空间等不因当前对手保护/替身/回避而失败 | `MOVE_RAIN_DANCE`、`MOVE_TRICK_ROOM`（7648 起），均为无普通命中且忽略保护 |
| 对手场地（`opponents-field`） | 隐形岩、毒菱铺在对方一侧，当前对手保护/替身不阻止；已有层数上限、重复失败等语义继续生效 | `MOVE_STEALTH_ROCK`（7857 起）；`BattleScript_EffectStealthRock`（3217 起）直接设置场地，不检对方单体命中 |
| 多个宝可梦（可能标作 `all-pokemon`，必须按效果识别） | 不可一概当场地技免检。黑雾是全场能力归零，参考明确忽略保护/替身；摇晃舞是对多个个体施加混乱，逐目标检查替身和命中。本项目单打也不能因此自动忽略对手保护/替身 | `MOVE_HAZE`（1994 起）与 `BattleScript_EffectHaze`（4026 起）；`MOVE_TEETER_DANCE`（5328 起）与 `BattleScript_EffectTeeterDance`（6421 起） |

“无命中率”只决定是否掷普通命中，不独立决定能否绕过保护/替身；“影响多个宝可梦”也不独立等于场地效果。沿真实目标与明确效果分类修复，不新增所有招式的世代规则重写。

### D4：保护和替身

既有保护/替身明确挡下的对敌招式，显示相应阻挡结果，目标不被下降能力或附加状态，白色香草不因这次被挡下的效果触发。不能显示阻挡后又同时宣称该效果已经命中并发生。

招式已明确允许绕过保护或替身时仍保留该例外；不把所有状态技都改为绕过，也不把所有声音/场地招式都按普通敌方单体处理。参考睡眠与降能力脚本均在效果前检查替身。此任务不要求重排所有既有失败原因的提示优先级，但必须保证单次行动只有符合实际原因的终态。

### D5：白色香草

命中后的实际降级使持有者至少一项能力低于 0 时，白色香草一次恢复全部负等级至 0，正等级保持；自身下降也能触发。只有从正等级降到 0、能力未变、被免疫/阻挡/未命中且没有发生新的下降时，不因此消费香草。此处的未命中用例从无既存负等级的正常状态起测，不能用人为预置的旧负等级混淆触发原因。

香草消费仅改变本场当前持有物；本局装备返还基准保持，下一场开战前返还。王者盾牌接触惩罚造成使用者真实降级并触发香草的既有已修路径应保留；它与被保护挡住的对敌状态技不是同一触发原因。

## 可判定结果

- 双方各自一次有数值命中的状态招式，分别观察命中与未命中；未命中无目标效果、无本次香草消费，PP 与行动只结算一次。
- 数值 100 的普通状态招式受已有命中/闪避修正；有明确必中条件的招式不被普通命中随机阻止，同时仍尊重适用性限制。
- 冥想等自用招式、求雨等场地招式，不因对手保护/替身/回避而新增失败；原有成功及无效条件保持。
- 普通对敌状态招式被保护或替身挡下时无目标效果、无香草消费；已有允许绕过的例外保持。
- 羽毛舞命中造成实际负等级→香草恢复与消费；同一招未命中→原能力、香草不变；下一战返还基准不变。自降与王者盾牌已修触发路径不回退。

静态测试、真实 UI 场景与模拟视口各自留证；具体夹具、随机控制和运行步骤由 architect 的验证计划确定，不能把本设计文档当运行验收。
