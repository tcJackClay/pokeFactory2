# PRD：派遣赠球与阿罗拉入口

orchestrator 拥有。依据本任务 `design.md` 及《公开版规则定稿》2026-10-14 用户决定。用户明确顺序：九道具和手机界面完成实玩验收、合入 dev 后，再实现本任务；此前允许完成规则与技术方案准备，不改业务。

## 玩家结果

F1. 现有地区派遣得到物品结果时，原成长道具与训练收益保持，额外免费获得3颗普通球。同一次结果只领取一次，不同次物品结果可重复取得。加入/可捕捉战斗结果不附送球；结果概率、地区物种池、派遣时间和原获取规则保持，不设新保底或每日额度。

F2. 球作为永久基地库存保存。开始/快速开始/继续/结束普通工厂及胜负不清除库存；普通工厂不能投球。现有派遣加入与可捕捉事件战从同一库存按原规则耗球；失败投球仍耗一颗，成功所得沿已验永久收藏登记。不得因工厂临时背包的清理导致库存丢失，也不得让两份库存相互回写而复制球。

F3. 同一结果的原奖励、训练、赠球与领取完成状态保持一致；重复点击、异步迟到、刷新、重开、同版导出导入不能重发。写入失败不能显示已领取却丢失奖励，也不能重试时多发。若不同地区同时领取或消费最后一颗，分别按真实已完成交易记录，不能以旧快照覆盖新余额或把一颗用两次。技术方案由architect沿既有交易架构提出。

F4. 阿罗拉既有妖精/幽灵/草资格增加岩石。只拥有已绑定岩狗狗的新档即可选择阿罗拉并开始原10小时派遣；其他永久岩石成员也适用。其他八地区、阿罗拉物种范围及原结果概率保持。工厂租借不因此成为派遣的永久成员。

F5. 玩家能在现有合适的基地/事件入口查看持有球数，领取反馈明确原奖励与新增3颗普通球；无球与写入失败信息准确，手机端可读可点。沿既有语言体系提供本次新增文案，不能把开发字段显示给玩家。architect提出最小界面接入点，不创建未经批准的商店或商品。

## 边界与约束

- 用户不要求兼容旧存档；若需升版本，沿既有明确拒绝/备份流程，不凭旧临时背包猜测永久库存。当前版本的合法刷新、重开、导入导出必须一致。
- 同版导入以所导入的完整合法库存与领取状态为准，不重新执行旧奖励，也不与当前库存相加。保留已有退出自动保存不覆盖导入档的保护。
- 库存计数与球种需验证，损坏数据不能变为负数、无穷数量或未知物品。具体格式归architect，不新增任意玩法限额。
- 不新增BP售球、高级球/大师球来源、捕获保底或捕获率调整；既有大师球文案与95%上限矛盾另行处理。现有零球派遣结果处理保持，不擅改为重新抽奖。
- 本任务涉及永久库存、领取及事件耗球，须独占相应存档/主hook/控制器接线；九道具与手机验收前不写入。后续高速旋转/TM实现顺序服从用户最新“先本任务”的决定。
- 事件战完整断点恢复是已记录的更广缺口；本任务仍必须保证已发放/已消费/已登记的永久交易不被刷新复制或丢失，不得借此宣称整场事件战恢复已完。

## 验收结果

1. 自然新档选择岩狗狗→基地→阿罗拉可派遣；显示/保存的10小时时长一致。六初遇的现有资格及其他地区有静态对照，租借不作为Owned混入。
2. 经真实UI领取物品结果，原奖励与3球同时出现；同一次重复领取不增长，下一次物品结果再+3；join/battle不额外赠球。受控时间/结果夹具必须明说，不能将时间推进宣称真实等待10小时。
3. 赠球后刷新/重开/同版导入保持；真实开启普通工厂并继续/结束后仍保留，普通工厂无投球通路。
4. 实际派遣加入和事件投球消费同一基地库存；成功/概率失败/无球/并发最后一球及写入失败重试有可重复验证，永久收藏登记与库存不矛盾。
5. 串行四门禁与独立auditor通过，最后冻结SHA由player以真实Go+Vite操作，主390×844及320×568/844×390边界页面有状态/截图。静态、受控模拟、自然入口及未验实体Android/生产分别记录。

没有必须再向用户确认的本切片规则。architect先写plan/context、标明最终整合基线与可执行验证方式，root批准后才实施。
