# 工厂内容规则台账：固定 TM50 与九种持有道具

日期：2026-10-13。designer 的规则与准入台账；不是技术实施方案，也不是运行通过报告。当前 TM 上架准入 **0/50**；九种持有道具名单及价格已定，逐件完整效果实玩仍须补齐。状态招式命中修复先行，战斗控制器的后续修改串行。

## 固定来源与共同门槛

1. 现行产品依据为 `docs/公开版规则定稿.md`、`docs/tasks/扩池规则/decisions.md`；工厂商店为第 3/6 胜后先换怪、再六件冻结货架，兑换券多件购买。所有历史文档中的“四卡/免费领取”只保留作历史研究，不是新任务契约。
2. TM 来源固定 Rogue expansion `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014`，本地 `output/rogue-expansion-reference/src/data/party_menu.h` 的 TM01–TM50；兼容性按普通 profile 的 TutorMoves 或 LevelUpMoves，不含动态 TR，不由工厂世代设置决定。
3. 每台 TM 必须同时完成 **项目 ID、固定正文、战斗效果、当前队伍可学且未学** 四项，价格档位也要按批准表接入后才可售卖；没有通过的项保持不上架，但不能从 50 项台账里消失或默默当作公开版删减。
4. 下表的玩家效果摘要来自固定 `src/data/battle_moves.h`、`data/battle_scripts_1.s` 及已核对研究，不替代源中的全部数值/标志/互动。architect 在每批 plan 中核对真实来源、当前代码及完整正文。若参考世代开关产生行为差异，designer 先给明确口径，不能以代码默认值冒充已批准。
5. 每项都要有玩家与敌方、有效与无效条件、PP/行动一次性、保存恢复的证据；概率/极端边界允许受控场景但必须标注。购买学习还要走真实六件商店 UI、合法目标、替换一招、一次扣券及下一战使用。模拟触控视口和 Android Chrome 实体手机分开记录。
6. 阶段状态统一用“待核对 / 已静态验证 / 已模拟实玩 / 已准入 / 已实体手机”。旧代码测试或截图只作历史线索，本页不能据此宣布当前逐项准入。
