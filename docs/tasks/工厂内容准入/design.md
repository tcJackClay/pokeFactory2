### 三件道具固定源复核（2026-10-13）

以下是**固定参考的静态事实与据此提出的验收口径**，不是运行证据。源根统一为 `output/rogue-expansion-reference/`，本次重新核验 HEAD 为 `a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014`。商品名单、券价及气势头带不消费的用户决定保持不变。

#### 编译配置与普通 profile

- `include/config.h:74,78–79`：`GEN_5=4`、`GEN_9=8`、`GEN_LATEST=GEN_9`。这是宏枚举值，8 不表示“第八代”。

- `src/pokemon.c:98–99` 同时包含普通与 revised 招式表；`include/pokemon.h:555` 用 `Rogue_GetRevisionModeActive()` 选择，并非只编译一张表。`src/rogue_controller.c:581–591` 的 revised 是运行设置；本项目已定普通 profile，采用 `src/data/battle_moves.h`。`src/data/battle_moves_revised.h` 不得仅因被编译就变成本项目来源。

#### K：王者之证

1. **K1 基础资格。** `src/data/items.h:6448–6458` 给出 `HOLD_EFFECT_FLINCH`、参数 10；`src/battle_util.c:8097–8118` 要求实际伤害非零、没有 `MOVE_RESULT_NO_EFFECT`、目标受伤且仍存活、招式没有 `ignoresKingsRock`、使用者不是恶臭特性，再做随机机会。状态技、未命中、保护/属性免疫导致未造成有效伤害、击倒目标均不能凭道具追加有效畏缩。`include/battle.h:811` 给出 `TARGET_TURN_DAMAGED` 实际伤害/挺住标志定义。
2. **K2 多段与防护。** `src/battle_script_commands.c:5741–5745` 明确每次连续命中执行道具检查；不能改成整招只判一次。`src/battle_util.c:8134–8139` 最终走 `SetMoveEffect(FALSE, 0)`；`src/battle_script_commands.c:2993–3015,3309–3329,3850–3853` 因鳞粉/密探斗篷、符合强行标志的招式、替身、精神力或目标已行动/极巨化而阻止相应畏缩。密探斗篷/极巨化在此仅是固定源边界，**不授权扩池或新增极巨化功能**。替身判断见同文件 `14950–14959`：忽略替身的招式/穿透特性例外仍须保留；不能一概认为“有替身就免疫所有畏缩”。本段不把普通替身受伤当成本体受伤，也不让破替身的一击错误追加本体效果；多段后续真正命中本体才重新按资格判断。
3. **K3 概率修正。** `src/battle_util.c:8102–8113` 在当前配置下天恩使道具机会翻倍；彩虹也有额外翻倍分支（秘密之力除外），恶臭禁止此道具分支叠加。`8076–8095` 的 Rogue charm/curse 是另外一套机制，本项目未批准，不能移植。基础 10% 不能被文案写成所有特性/场地下一律 10%。未支持的互动列入范围核对，不能冒充已实装。
4. **K4 已有畏缩招式：用户已批准独立判定。** 用户 2026-10-13 明确选择「按固定 Rogue 参考独立判定」。普通表 `src/data/battle_moves.h:7086–7100` 恶之波动自带 20%，`7796–7810` 铁头自带 30%，两者都没有设置 `ignoresKingsRock`（未写字段为零）；revised 表 `7356–7370,8105–8119` 也相同。主招式概率在 `src/battle_script_commands.c:3855–3872` 判断，道具另在 K1 分支判断。无其他修正且目标满足所有资格时，两次机会的数学结果为 `1-(1-p)*(1-0.1)`，分别为 **28% / 37%**，不是 30% / 40%，也不是“已有概率就完全不加”。这两个数是源码规则推导，**不是源码中的常量或运行 ROM 统计**。当前项目 `src/features/game/lib/battleResolution.ts:858–871` 使用 `Math.max(招式概率, 道具概率)`，对应 20% / 30%，并且强行只清掉招式概率、仍留下道具机会；这些差距由后续九道具任务落实，不能写成已修复。K1–K3 的有效伤害、多段、替身、免疫与特性修正同样适用；一次行动至多失去一次，不能因两个机会都触发而扣目标两次行动。

#### M：心灵香草

1. `src/battle_util.c:7143–7196` 的 `GetMentalHerbEffect` 完整集合为：迷恋（7147–7153）、挑衅（7157–7164）、再来一次（7165–7172）、无理取闹（7173–7179）、回复封锁（7180–7186）、定身法（7187–7194）。后五项在 `B_MENTAL_HERB >= GEN_5` 内，当前为第九代，全部启用。
2. 这些是顺序独立的 `if`，一次触发可以解除并存的全部合格限制；再来一次和定身法同时清计时及绑定招式。不是随机挑一个解除，也不是只处理 UI 文案中列举的前两种。
3. `src/battle_util.c:7360–7367` 只在返回实际清除成功时进消费脚本；`data/battle_scripts_1.s:10100–10107` 的 `removeitem` 消费一次。无合格限制不消费；它不解除普通睡眠、中毒、灼伤、麻痹或混乱。战间返还按本项目已定规则另行恢复。
4. 当前项目 `src/features/game/data/battle/itemEffects.ts:137` 列表含 `attract/infatuation` 两个迷恋命名及其余四类，**缺回复封锁**；`useBattleController.ts:718–733` 会清当前列表中所有已存在状态并消费。全库只搜到 `battleLogText.ts:21` 的 `heal_block` 标签，未据此确认回复封锁有完整施加/限制/解除实现。因此九道具任务必须明确这个覆盖缺口；不能因没有自然生成入口就声称完整六类通过，也不由本规则文档擅自扩成“实现全招式”。

#### H：厚底靴与毒菱

1. `src/battle_util.c:11639–11654` 的 `IsBattlerAffectedByHazards` 对有效厚底靴返回不受影响；但仅读这个函数会漏掉吸收顺序。
2. 真正入场路径 `src/battle_script_commands.c:7111–7124` **先**要求有毒菱且接地，**再**判断毒属性并清本侧全部毒菱，最后才对非毒属性调用靴子免疫。故接地毒属性穿靴也清掉一/两层；非接地毒属性不吸收；非毒属性穿靴不中毒且毒菱留场。隐形岩与黏黏网分别在 `7100–7109,7146–7155` 先检查靴子免疫。这里不授权新增当前没有的陷阱。
3. 当前 `src/features/game/battle/engine/resolveEntryHazards.ts:54–55,70–87` 已采用“隐形岩免伤；接地毒先吸收；其余目标靴子免疫毒菱”的顺序，**这不是已发现需改代码的冲突**。九道具验收补双侧、换人/补位、接地/飞行、毒/非毒、有无靴、两种陷阱同场即可。靴子不消费；无陷阱不伪造收益日志，普通战斗伤害不获免疫。
