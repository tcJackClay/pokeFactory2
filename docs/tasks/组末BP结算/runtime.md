# 组末 BP 结算试玩验收

测试时间：2026-09-26。运行版本：`13a7a85` 加当时工作树未提交改动；前端 `127.0.0.1:4300`、Go 服务 `3001`。测试使用独立 Chrome 浏览器上下文与 `127.0.0.5:4300` 源，未读写用户正在使用的 `127.0.0.1` 浏览器存档。新建存档为 v9，起始钱包 0 BP。此记录只覆盖浏览器真实运行；第 1 战出招后，其余胜利使用开发者面板的 Win 按钮。

## 七战主路径

| 操作 | 浏览器画面 | 本地存档钱包 |
| --- | --- | --- |
| 新档选 3 只租借并进入第 1 战 | 约 24.7 秒生成 6 张租借卡；可选队并进入战斗 | 0 BP，`settledThrough=0` |
| 第 1 战使用一次「报仇」 | PP 从 5 降到 4，对手受伤并使出「宇宙力量」 | 0 BP |
| 第 1 战胜利 | 结果页「前往换怪」，没有奖励卡 | 0 BP |
| 交换页 | 我方和敌方各 3 只，可选敌方「科斯莫姆」并确认交换，也可跳过 | 0 BP |
| 第 2～6 战胜利 | 每场结果页均「前往换怪」，无奖励卡；主连续路径选择跳过交换 | 全程 0 BP，`settledThrough=0` |
| 第 7 战胜利 | 结果页显示「基础 BP 3」「本组实际获得 BP：+3」「当前 BP：3 / 9999」 | 3 BP，`settledThrough=1`，`lastSettlement.setNo=1`、`stage=7`、`amount=3` |
| 返回基地、刷新、重开第 7 战结果页 | 均显示 3 BP | 仍为 3 BP，`revision=2`，未重复入账 |

第 1 胜交换页选择敌方后进入第 2 战训练家对白时，刷新会回到第 1 战交换页；在对白上点击继续、敌方上场后，存档随即更新为第 2 战 `READY`。跳过交换路径也有相同的安全检查点行为。先前观察到的“第 2 战画面但存档仍为第 1 战”发生在训练家对白尚未确认时，不能作为丢档缺陷。

七战连续操作的逐场钱包、快照和画面文字记录在 [seven-run-observations.json](evidence/seven-run-observations.json)。[第 1 战真实出招](evidence/390-stage1-real-turn.png)、[第 1 战换怪](evidence/390-stage1-swap.png)、[第 7 战结果](evidence/390-stage7-result.png)、[基地刷新](evidence/390-base-after-reload.png)是对应截图。七战循环捕获的浏览器控制台错误及 HTTP 400 以上响应均为空；初次租借生成时曾见一条瞬时 502 资源响应，但生成最终完成，未保留该响应 URL，不能据此判定服务问题。

## 组末继续刷新窗口

## v10 修复后回归

测试时间：2026-09-26。运行版本：`13a7a85` 加随后工作树修复，存档版本 v10。新建独立 Chrome 上下文，源为 `127.0.0.6:4300`；没有导入 v9 样本，也没有操作用户原 `127.0.0.1` 存档。以下结论只对应这次测试时的工作树，后续跨页修复尚未纳入。

新档默认 `selectedGens=[1]`。在设置页选第九世代后，`selectedGens=[9]`，刷新并重进设置仍只选中第九世代。正式开始挑战约 11～14 秒生成 6 只租借：ID `915, 940, 946, 963, 932, 928`，均属于第九世代。设置页在 320×568、390×844、844×390 截图可见，页面没有横向溢出：[320×568](evidence/v10-settings-320x568.png)、[390×844](evidence/v10-settings-390x844.png)、[844×390](evidence/v10-settings-844x390.png)。此处只验了设置布局，未对三个尺寸都跑战斗。

本次第九世代七战均用 DEV Win 辅助。第 1～6 胜后钱包一直为 0，结果页进入换怪且无奖励卡；第 7 胜后钱包为 3 BP，`settledThrough=1`。六租借与逐战本地状态在 [v10-seven-run.json](evidence/v10-seven-run.json)，[第九代租借](evidence/v10-gen9-rentals.png)及[第 7 胜](evidence/v10-gen9-stage7-result.png)为截图。本次循环未捕获浏览器控制台错误或 HTTP 400 以上响应。v10 七战没有真人出招胜利覆盖；v9 回归中只完成过一回合真实招式。

第 7 胜回基地，存档 `READY/BASE`、`stage=7`、3 BP。点「继续挑战」约 120 ms 后立即刷新，刷新仍恢复 `READY/BASE`、`stage=7`、3 BP，并保留「继续挑战」。再次点击后进入第 8 战 `READY/BATTLE`，余额仍为 3 BP。旧 v9 续战刷新窗口在此 v10 样本中已修复。[窗口前后状态](evidence/v10-continue-window.json)、[刷新后基地](evidence/v10-set2-continue-reloaded.png)、[第 8 战可操作画面](evidence/v10-stage8-ready.png)为证据。

另发现发布阻断：从第 7 胜后的 `READY/BASE` 基地进入「设置」，存档立刻变为 `EMPTY`、`stage=null`，但 `challengePaused=true`；刷新后基地仍显示「继续挑战」，画面连胜显示 0，原可续检查点已丢。钱包仍为 3 BP。见 [跨页前后状态](evidence/v10-base-settings-reload.json)、[进入设置](evidence/v10-set1-settings.png)和[刷新后基地](evidence/v10-set1-settings-reloaded.png)。此问题已反馈给程序员，尚未在本记录中复测修复。可续局时设置页可进入，页面提示应先完成或结束挑战再修改世代；本次未实际点其它世代选项，故「不可改」行为仍待验证。
