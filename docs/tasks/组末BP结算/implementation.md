# 组末 BP 结算实施记录

日期：2026-09-26。

已将 Classic 工厂单打改为七战整组结算。前六胜不入账；第七胜按本地 `pokeemerald-expansion@ca17c6a3d40a` 的 30 档单打表一次入账；任一战失败或主动退出将本组记为 0 BP。余额上限为 9999，结算记录同时保留名义 BP 与实际入账 BP。组键为当前挑战 ID 与组号，`settledThrough` 是当前挑战已结算的组号高水位；旧组重复回调不再入账，下一组可继续结算。

工厂首领使用独立 `TRAINER_NOLAND` 训练家身份。出场条件依象征数与当前连胜判定：未得象征在第 21 战、已有一个象征在第 42 战、已有两个象征后在第 21、42 战及其后每隔 21 战。仅实际对手身份是 Noland 且整组获胜时增加 10 BP，象征数与钱包在同一次同步写入中更新；普通第七战没有此加成。

BP 任务最初将存档版本升至 9；同期世代单选任务已将当前版本升至 10。旧版本导入会明确拒绝；本机旧档显示备份和清除入口，旧逐场代币余额不会转入 BP。新版本将 `ROUND_RESULT`、`FACTORY_SWAP`、组末回基地待续挑战记录为可恢复阶段。组结算同步写入钱包及结果阶段；旧闭包自动保存会合并高版本钱包，并保留同一场已提交的结果快照。写入失败保留战前检查点与当前标签页的待重试意图：同标签刷新可重试原结算，关闭标签后仍可重打原战。换人选择在下一战生成成功后才提交，失败时可重试；动作门仅在生成成功后标记完成。

玩家界面将结算与余额标作 BP，组末展示基础 BP、真实首领额外 BP、实际到账和当前余额。战斗日志本地化任务新增的六处 `currentLanguage` 参数已由控制器接线；控制器其他直接拼接的英文消息不属于本任务。

验证：`npm run lint` 通过；`npm test` 113/113 通过；`npm run build` 通过；`go test ./...` 通过；`git diff --check` 通过。聚焦测试覆盖完整 30 档、前六战零入账、第 1–3 组、首领身份及周期、失败 0、重复结算、9999 上限、写入失败重试、旧档拒绝及 DEV 跳组基线。真实浏览器与手机的七战、刷新、触控和可见状态仍需 player 独立验收；这些静态结果不代表运行验收完成。

运行验收发现并修正第七胜后回基地继续挑战的加载窗口刷新丢失存档问题。继续按钮现在保留组末 `BASE` 检查点和待续标记，直到下一战的稳定 `READY` 快照生成后才清除；生成失败仍回到原 BASE 并可重试。新版本即使加载窗口曾写入 `challengePaused=false`，也能从有效组末 BASE 快照恢复待续状态。针对性状态测试覆盖加载中、生成失败与生成成功后的检查点释放。控制器战前状态消息的中文对手前缀也已修正；初始世代选择采用单一第一世代，并只读取存档首个世代。再次通过 `npm run lint`、`npm test` 116/116 与 `npm run build`。player 需要按 `evidence/set1-continue-window.json` 同一路径复测刷新窗口。
